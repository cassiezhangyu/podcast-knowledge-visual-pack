# 图片内容规划：逐页存在性与论证深度

本规则在已获确认的《内容梳理》《内容拆分》之后、绘制 Page Content Pack 之前使用。它审查页面是否有独立解释任务；`coverage` 完整、细节 ID 已分配和页码连续只是输入条件，不能代替本审查。

## 0. 页面类型职责与全文核心覆盖

先按读者应获得的理解确定页面类型，再分配材料。页数与版式服从这些职责：

| 类型 | 阅读任务 | 完成判断 |
| --- | --- | --- |
| 封面 | 识别节目并建立阅读动机，以忠于全文的钩子引入核心问题 | 读者知道是哪一期、主要讨论什么、为何值得继续读；详细规则见 `cover_page_production.md` |
| 总览 | 用一张完整图汇总全文核心内容，建立节目级理解框架 | 未听节目者只读该图可复述主要知识或核心判断及其关系、范围和必要边界；复习者可快速恢复整体，见 `overview_page_production.md` |
| 深度解读 | 围绕一个独立问题，展开总览中的知识与判断 | 读者获得总览尚未讲透的原因、机制、证据、案例辨析或使用边界，见 `deep_dive_page_production.md` |

内容地图与本页提纲是定位工具，来源页脚是回听与追溯工具，均不能替代正文解释。若确需附录视觉页，写明其独立查阅任务与内容去向，并计入整包页数；不以附录存放本应可见的核心观点。

规划总览时，从已批准的全文内容提取「核心观点 → 总览中读者能复述的判断及关系 → 深度页的具体展开」对照。覆盖单位是实际观点或知识关系，模块数不等于观点数，不要求每个细节都在总览出现。同一内容单元包含多项独立核心判断时，分别登记并核对，不能凭一句概括或一个已出现的单元 ID 将其全部记为覆盖。独立应用、反方判断或后半段讨论若改变整期理解，应保留其核心判断及与主线的关系；次要例证可进入深度页，并记录理由。只有板块名、问题名或页码的条目不算核心观点已覆盖。

分别核对两种完整性：**全文核心是否在总览可见**，以及**必留细节是否有明确深度页去向**。后者全部有去向，不能证明前者成立。总览续页按专属协议验证；材料只需要具体展开时，将其分配给深度页。

在选择总览主表达前，先从已确认内容说明节目级框架，再核对标题、整页结论、主视觉与主要区域是否保持其关系和主次。局部观点、机制、对照或案例承担主表达时，说明它承载哪些节目级关系、哪些主要判断仍需独立呈现；不能只凭观点逐项覆盖或主命题文字未变，认定框架已保持。若改变上游中心或从属关系，在现有规划中突出变化、原文依据及审批影响。此项语义核对在提交规划前完成，不能由ID、数量或哈希检查代替。

### 总览的统一载体（必答）

提交总览规划前，用一句话回答：**全期内容放在同一个什么对象、系统或空间上看，各主要部分分别是它的哪一部位或哪一种状态？** 例如：EP86 把全期放在“一条交付流”上，入口是需求取舍，管道里是五种流不动，回流是持续改进，三种实践分别作用在入口、管道和回流；EP88 把全期放在“土壤托起植物”上。载体来自来源已有的对象，或来自整理者有依据的综合；规划里写明属于哪一种。来源确实只有并列问题时，载体可以是“同一把尺上的几个落点”这类并列容器，但仍要写明并列的共同基准。

反目录自检，任一项回答“是”就退回重写框架，不进入选色和三案：

1. 主要部分的排列顺序是否只是节目讲述顺序？
2. 去掉编号以后，各部分之间是否就没有能画出来的关系？
3. 实践、方法或个人应用是否只是另起一段，没有说明它作用在载体的哪一部位？
4. 主视觉能否用“读者先看到……，于是明白……”一句话说清？说不清就不成立。

**框架确认停点**：总览画三案之前，先把“载体、各部位与内容的对应、关系授权表”用文字示意（列表或 ASCII 简图）交用户确认，并写入 `OVERVIEW_RELATION_LEDGER`。三案只在确认后的同一框架上探索不同组织方式。用户否定框架时，三案全部作废，回到本节重做框架，不在旧框架上换构图。

### 必要细节的筛选

先明确判断，再选择承担依据、解释、反例或边界的案例。读者从完整图文应能说清为何列举该例、它如何支持或限定判断；需要补足哪些事实由读者前提决定，不强制每例具备同一叙事句式或固定位置。判断职责不能只藏在案例中，图已表达的含义也不必再完整复写。遮去案例仅用于诊断主次与归属：案例本身承担核心解释时，不以遮去后的信息损失直接判失败。

来源完整保存在内容底账；上图只保留解释观点、提供判断依据或防止关键误读所必需的细节。对候选细节先问：拿掉它，读者是否会不理解本页观点、失去决定性依据，或误判结论的条件与范围？在现有逐页规划中记录它支持哪个判断、承担解释/证据/边界何种职责，以及保留、合并为代表证据或仅留来源的理由。不用细节条数或逐字保留率衡量画面完整性。逐项说明拿掉该项会损失哪个判断、依据或必要限定；相同职责可合并说明，不能用同一句“保留判断与限定”代替必要性判断。已批准规划的复核先保留原件：只改变表达而保持含义时记录映射，删改核心判断或关系时走既有规划变更审批。

同职责的例子选择足够支撑判断的代表，不逐项枚举；图已清楚表达的范围、状态或比较不再用长段复述。移出某个支论点时，其专属例子和限定一同回到底账；保留该论点时，影响含义的主体、模态、条件和边界必须随它保留。不能只删限定、留下更强结论，也不能因难画而删决定性支撑。

先筛必要性，再做信息预算与图文分工。将所选含义按读者需要完成的追踪、比较、辨别或条件判断，合并为实际理解任务；在现有内容包与text_graphic_split中说明哪些判断由同一结构共同承担、哪些条件紧贴判断、哪些原句不再重复。逐项有保留理由不证明组合后容量合理。只有必要判断和依据经重组仍无法在正常字号下可读，才讨论容量或页数；不设通用字数目标。历史清单标为“必留”但无法说明当前论证职责时，回到本阶段修订内容合同，不能在构图中偷偷删减，也不能将旧清单全部写成长文。

## 1. 从总览出发决定每张深度页的新增理解

先用一句话复述总览已经让读者知道什么，再为每张 Deep Dive 写一句**总览尚未解释、读完本页才能理解的判断**。接着列出使该判断成立的机制或关系、具体证据/案例、成立条件与边界，并把每个必留 detail ID 分配到论证步骤。若页面只能重复总览标题、改写方法口号或放大同一案例，返回内容规划重新定题；不以更大字号、留白或图形补足论证。

标题问“为什么／怎样”时，论证路径必须真正回答原因、过程或判断方法。主机制不应只留在 Page Content Pack 或旁注里，却让反例、结论或三条标签占据主图。

## 2. 用相邻页检验存在性

对每一对相邻页面分别回答：

1. 前页留下了什么具体问题，后页新增哪一步理解？关系是依赖、例证、反问、对照还是并列？
2. 把两页合并后，哪一组必要证据、边界或独立问题会失去可读空间？若说不出，优先合并或重定题。
3. 同一概念在两页出现时，各页承担什么不同职责？例如一页建立概念，另一页解释实际操作或反例；若答案句相同，消除重复。

多组案例同页时，要有来源支持的共同页面问题和可比较维度；不同人物、任务或讨论只能因明确的并列/对照职责同页，不能被版式画成因果或必经顺序。一个内容单元可跨页承担不同作用，但其具体 supporting detail 必须有清楚的主去向，重复出现要说明新作用。

## 3. 按论证和阅读容量决定合页或拆页

先写每页的论证步骤、必留细节、主案例、条件和边界，再估计单页能否在系列画布与手机预览中真实呈现。**封面、全部总览（含续页）、全部 Deep Dive 与随组图交付的附录视觉页合计不得超过 18 张。** 内容关系决定如何在这项硬约束内合页或拆页，不能由时长、模块数、历史页数倒推页数。超过上限时先找共享页面问题的材料并重审容量与来源去向；若合并会造成微字、边界丢失或错误关系，保留冲突记录并暂停正式成图，不用超额页面或静默删内容绕过门禁。

- **合页成立：** 两组内容共同回答一个页面问题，合并后每组证据和边界仍有清晰位置；材料入口可以作为另一论证的旁证，但不能把不同主体的动作冒充同一过程。
- **拆页成立：** 存在两个可独立回答的问题或解释层，且同页会使其中一层变成口号、案例清单或微字；拆开的页面还必须各自有完整论证，而非只为增加页数。
- **容量未定：** 内容上可以同页，但案例多、外部事实风险高或关系复杂时，记录具体的拆页触发条件；到 Page Content Pack 与真实 390px 图复核。尚未证实信息折损时，不提前锁定新增页。

## 4. 审核记录与完成条件

在 `page_content_plan_proposal.json` 为每页记录问题、结论、必要细节及 evidence anchors，并在 `图片内容规划.md` 或等价逐页审查表中记录：新增理解、主解释关系、重要案例/边界、与前后页不能合并的理由、容量风险和触发重审的条件。详情要进入论证步骤，而不只出现在覆盖矩阵中。

### 主图语义构思的用户审阅面

在同一份 `图片内容规划.md` 中、请求规划批准前，加入简短构思说明。它汇总现有主解释、图文分工及关系记录，不另建同义schema或新增人工门禁：

- 本页让读者理解哪项判断，来源支持哪种关系；主图、支撑、条件、反例、独立线和辅助信息各承担什么职责。总览同时展示第0节框架核对的结论；涉及主次或关系变化时，将它列为当前确认项，不只列模块名和构图方向。
- 逐项选择适合的表达：对象、流程、对照、层级、范围、数量或必要文字。重要性先由内容决定，不能因为难画而降级或删掉关键判断；表达不暗示未经来源支持的机制或计量。
- 用一段自然语言讲清先看见什么、怎样形成判断、其他部分怎样补足或限定、不能推出什么。不用坐标、画法术语或固定入口—循环—出口句式。
- 说明主辅空间的分配理由和容量风险。主图面积随解释职责确定，不规定半页；并列内容不为一体感强接主线，导航与来源保留正常可读空间。
- 默认三案时，列出同一内容的三个构图方向及各自理解收益，确认内容与表达关系后再做真实草图；不是让用户提前批准像素质量。

用户在现有规划门禁确认这些语义职责和构图探索范围后，再选色和绘制。概念确认、草图准入、完整历史等级和最终选图是不同状态。恢复旧批准规划时：语义与范围不变的补充说明可绑定旧批准并记录；新增或改变关系/职责、或用户未见过需要批准的构思时，提供具体补充规划并等待该补充确认，不把更新Skill当作批准。

提交用户审核前逐项确认：

- 封面、总览、深度页各自完成上表的阅读任务；全文核心覆盖对照无未说明缺项，总览可独立复述，且各深度页的新增理解可定位；

- 计算 `1 + 总览页数 + Deep Dive 页数 + 随组图交付的附录视觉页数 ≤ 18`；页面清单、右栏地图与页脚分母按同一计数。超额提案先重排，不能提交审批或进入组装；

- 每页能让读者获得一项相邻页和总览无法替代的理解；
- 每个必留细节都有论证职责和唯一主去向，重要反例、条件与归属没有被压成页脚；
- 合并与拆页的理由指向内容损失或真实阅读容量，而非版式整齐；
- 两页间的递进、并列或对照有来源支持；高容量风险页有明确的成图复核点。

有一项无法说明时，记录待修订项，不送用户批准或开始绘制。机器去向检查可以阻止遗漏与重复记账，不能给出“每页值得存在”或“已经讲透”的语义结论；用户仍需审核页面分工。

如果连续视觉候选因同一主解释缺口被判 `REJECT-B`，先回查本页新增理解、主机制与证据分配；问题在页面合同时返回图片内容规划，不继续只换构图。已获用户通过的其他页面保留为基线，只复核受影响的跨页关系与正式规划绑定。

已批准的页面在制作中若要把细节迁往另一页，修订提案须同时列出迁出页失去什么、接收页怎样使用每个细节，以及接收页的论证和手机容量风险；同步更新受影响页的内容包与覆盖去向。新旧合同分开标记：提案可用于讨论图样，但在用户确认修订内容并重新绑定规划之前，候选不能被登记为按新合同通过的正式页面。若接收页真实成图后出现微字或证据缩水，回到两页分工，而不是在画面里静默删除迁入内容。

## 5. 用户指定生产范围

用户指定 `production_scope`（见 SKILL.md Input Contract）时，仍先按第 0–3 节规划全文覆盖：总览骨架和封面副标题照常写，范围外的页面不制作。范围外细节的主去向写 `OUT_OF_SCOPE`，并在《图片内容规划》里说明暂缓原因和将来的去处。定向 Deep Dive 先把用户的主题映射到已批准的模块或内容单元，映射本身也要交用户审核。页数上限只计算范围内的页面。
