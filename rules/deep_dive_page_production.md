# Deep Dive 逐页生产协议

本协议补充 `page_visual_production.md`，用于把已通过《内容拆分》的模块制作成可审核的 Deep Dive。内页按 `inner_page_module_contract.md` 保持外围模块职责；正文构图、地图和提纲位置由内容决定。来源归属、图形装配、视觉权重、内容覆盖与文字几何按本协议、逐页生产规则和 `taste.md` 检查；补充参考见 `acceptance_case_index.md`。

## 1. 先锁定页面问题

页面类型与新增理解先按 `rules/page_content_planning.md` 第 0–1 节核对：本页展开总览中的一个具体问题。冻结内容包时写明它新增的原因、机制、证据辨析或使用边界；总览已经给出的概括只作必要入口。整包末页依据实际节目内容收束核心判断、边界或未解决问题，保持来源支持，不为凑收束形式新增一张总结页。

从 Page Content Pack 提取并冻结：

- 本页只回答的一个问题与一句结论；
- 结论成立所需的观察、动作、状态变化、案例和边界；
- 本页不承担的内容；
- 每个可见专名、编号、数值和引语的来源。

内容包没有的事实不得为方便画图而补入。内容包冻结事实、动作、案例与边界，不得提前强加来源没有的视觉道具、人物场景或产品界面。需要表达视觉连续性时，使用相同对象形态、颜色、标记和普通名称；不得自造看似来自节目的编号或数据。

为页面中的关键句标记来源强度：

- `fact`：来源直接陈述的事实、数值、引语或动作；
- `case_inference`：由多项来源事实支持、且明确限定于当前人物或案例的解释；
- `general_claim`：可推广到其他案例的判断，必须有独立证据，不能由单一个案自动升级。

页标题、模块标题和底部结论比正文更醒目，必须逐句检查主语、范围、条件和语气强度。正文正确不能抵消标题中的过度断言。重组内容后重新核对数字、时间、案例和限定是否仍可见，不能让抽象模型吞掉支持细节。

高权重文案若来自单一个案，直接在标题、副标题、模块标题或总结句中写明人物、产品、时间或案例范围；不要依赖正文中的限定替醒目文字补充边界。`case_inference` 只能解释当前案例，只有独立证据支持时才能写成 `general_claim`。

## 2. 内容、案例与审美联合预检

在选择具体构图前，先按 `rules/page_visual_production.md` 的“阅读拓扑门禁”记录主方向、段落顺序、段内方向、入口与收束，并逐项记录相邻主要区域的内容关系。该记录描述当前内容怎样被阅读、为什么从一个问题进入下一个问题，不规定固定的上下、左右或三段模板。

页眉、右栏和页脚是系列外围合同，不是正文的预设槽位。先从本页内容提取要对照的对象、可见变化、反证与边界，再依这些关系分配正文的形状、面积和位置；不预先划出等权的上／中／下三块，也不要求每页复用同一种左右或内外结构。纵向分段只有在内容本身确有顺序、且该顺序能帮助读者看见论证时才采用。构图后回看真实 PNG：若只需替换每块文字就能用于别的主题，或编号与分隔线比内容关系更主导画面，返回视觉方案重组。

当多个横向长分隔线把正文切成相似高度的材料行时，逐条删除后检查：对象之间的归属、并列或先后关系是否仍可辨认。若只是把“标题＋图标＋说明”排成层叠清单，应从内容关系重新构图；不要以减少线条数量但保留同一行列拓扑充当返工。只有来源支持的阶段边界、真实基线或对象连接才保留相应线条。

构图前，创作者必须分别完成以下输入，三者不能互相替代：

1. 读取完整 Page Content Pack；
2. 实际打开相关正例、反例和同系列已通过页面；
3. 读取当前 `taste.md` 与 `design_tokens.json`。

保存各输入的路径、版本或哈希。联合预检必须回答：

1. 正例怎样用具体图形、逻辑关系或文字层级降低理解成本；实际画出的对象、动作或状态是否无需标签抢救；
2. 反例中的线条、图标、标签或流程为何需要正文抢救；
3. 当前页允许与禁止的图形语言；
4. 当前系列的画布、色值、字号、页眉页脚和手绘纹理合同。
5. `taste.md` 中哪些原则改变当前页的主解释结构、对象与图文分工；
6. 当前方案是否落入 Card Grid、Editorial Article、Node-only Flow 或 Abstract→Abstract。

只读 `taste.md` 不算完成案例预检；只看案例或已通过页面也不算完成审美规范预检。审核者后来读取这些输入，不能补签创作者缺失的预检。联合预检未保存，不进入 scene 构建。

联合预检只是假设，不是通过证明。首次真实 PNG 生成后，建立一次「规则→像素」对照：

- 每条被采用的关键原则指向当前 PNG 里的可见对象、状态或图文分工；
- 每个预检中拒绝的失败模式都用当前 PNG 重新复核；
- 若预检声称“不用抽象线条”，当前图却只剩抽象线条和标签、图文结合也未增加理解，则预检执行失败，不得送审。必要短标签可帮助识别对象。

### 首读自明检查

构图前把读者设为「未听节目，只看这一页」。逐句检查标题、图注、案例、边界和旁注：读者是否知道**谁在说、说的是哪件事、依据是什么、与本页结论有什么关系**。对节目的物件举例，先点明其来源与论证职责，再画物件；对网络缩语、圈内称呼和抽象代词，写出普通读者能直接理解的具体对象或动作。跨到另一个案例时，交代共同问题，避免视觉邻接暗示同一因果链。

转述与观察在醒目文字及具体陈述附近标明主体和证据强度；单一见闻只写成该人的观察或判断，不能靠页底的边界句事后收回正文的确定语气。旁注要能回答它为什么留在本页；若属于相邻页的问题，按已批准页面合同移回对应页，不能靠「节目还谈到」把游离内容塞入空白。

首读检查完成标准：让独立于创作者的读者仅凭当前完整原图（含必要文字）复述主要例子的用途、两个相邻模块的关系和关键归因；复述错误先改内容或图文连接。可暂略长说明来诊断图的贡献，但不要求图独自完成复述。每次改写都重新渲染原图与 390px 图，逐行核对真实字形与栏界；`scene.width` 和静态检查通过不能证明末字没有越框。局部文字修复只解决当前歧义，整页原有视觉等级和手机可读性问题仍单独记录。

## 3. 内容驱动的主体创作

新构图与主结构重做按 `visual_creation_context.md` 及 `visual_reasoning.md` 执行。来源给对象、动作或状态时验证实际部位；来源只给条件、并列或解释归属时，使用准确关系和必要文字，不补造过程。趣味来自内容专属的可见差异、可信对象和画面组织，不来自添加无关道具。

简单准确关系不因“只有一层”自动失败；它是否足够回答本页、占据适当分量，由真实核心检查。完整审美仍须与实图参考比较。物件或载体只收纳段落、界面只是改名的框时，改变图文职责与构图，不用纹理或更多线条补偿。历史失败案例按 acceptance_case_index 命中后再读，不作为每页默认构图指令。

### 语义归属与视觉权重

构图中的位置会改变读者对内容归属和主次的判断。对每个关键文字块、图形和问题组记录它属于哪个案例、对象或共同结论：

- 案例专属的事实、解释、追问和边界留在该案例的空间轨道内；只有多个案例共同支持的结论才能跨栏或跨区；
- 不能因为文案写着对象名称，就忽略它紧接另一案例所造成的视觉误读；
- 并列内容比较可用面积、标题等级、对象尺度、视觉墨量、细节数量和阅读时长；这些信号形成的主次必须与 Page Content Pack 的论证主次一致；
- 等权内容出现明显视觉重量差时重构；有主次内容被排成等权时同样重构。等宽只是一种可能的修法，不是默认模板。

### 整体对象与局部机制

局部结构、截面或放大图负责解释部件关系，不能独自承担对象身份。遮去名称后，如果读者不知道局部属于什么对象，先建立完整对象、使用场景或足够的整体形态，再进入局部。整体对象负责“这是什么”，局部图负责“它怎样工作”；连接箭头只在两端对象均已成立后使用。

### 对象装配与状态一致性

完整对象可识别后，继续检查关键部件是否真的属于该对象。每个承担机制解释的部件都要能在真实 PNG 中回答：装在哪里、与谁接触、沿什么方向作用、改变了什么。部件不能悬浮，连接不能只靠邻近或标签暗示；若多个零件组合后形成与真实对象无关的十字、靶心或通用机械符号，重画对象结构。

同一状态图中的对象位置、部件状态、动作说明与结果文字必须一致。若需要表达连续动作，使用可区分的起点和终点，或明确标出当前画面处于哪个时刻；不得在“已打开”的对象旁画“正在闭合”的部件状态，再用文字解释矛盾。

### 解读层门禁

Deep Dive 不能只把来源事件、数字和引语排得更清楚。每个主要模块应形成：

`来源事实 → 关系或机制解释 → 当前案例的结论／边界`

若读者只能复述“发生了什么”，却不能回答“为什么这组证据支持本页结论”，返回 Page Content Pack 或视觉解释方案。解释必须保留证据支撑，不得为了显得深刻而写成来源不支持的格言。

每个相邻主要区域还要回答：前一区域已经解释了什么，为什么会产生后一区域的问题，后一区域用什么证据、案例或机制推进本页结论。把关系写进构图前的 `module_relations`，标明来源支持的关系类型与禁止读出的因果、先后或一一对应。若只是同一问题下的并列案例，就用共同问题和对照维度组织，不能为了形成箭头链而改写成递进或因果。单个区域的事实与解释都正确，但区域之间无法回答“为什么接着看这里”，仍应返回页面内容规划或视觉解释方案。

### 边框语义检查

矩形边界只用于表达真实对象、对象内部状态、明确的约束边界，或无描边的阅读区域。若一个框只是在整理排版，优先用位置、字号、留白、浅色区域、分隔线、基线或开放主轴建立结构。逐项询问：删除这个边框会不会损失对象或关系含义；不会时删除边框。减少边框后必须重新检查阅读顺序和模块边界，不能以“开放构图”为由制造散乱。

窄区域不默认拆成双列。两栏都必须有足够正文宽度、明确入口和稳定对应关系；删除栏界后若对应关系随之消失，局部必须重新构图。高信息区域同样执行“五秒下一步测试”，不能只检查整页主链。

## 4. 图形完成度与 Excalidraw 调性

- 人物、物件和动作必须有闭合轮廓、稳定比例、可辨识部件和明确连接点。
- 禁止用火柴人、巨大叉号、星芒乱线、随手波浪和自由大轮廓替代机制。
- Excalidraw笔触按handdrawn_strokes区分职责：具体插图保留自然笔触与局部复描，排版线及信息框克制，不能满页明显双线或人为弯曲直线；不以roughness掩盖粗糙对象。
- 文字保持干净；长分隔线的 roughness 低于对象轮廓和动作连接线。

首次渲染后，对实际绘制的对象图做一次诊断：暂略长说明，检查对象与线索是否有可见依据；保留必要短标签，恢复完整文字后，比较图文版与纯文字版的理解效果。不以遮字后能否独自复述论证判级。同时为每条可见线条确定职责：对象轮廓、真实部件、状态变化连接、分隔或基线。没有可见职责、起止点或对象的线条必须删除；核心对象错误或图文合起来仍无解释价值时返回视觉方案。文字主导区域按主次、关系、证据和阅读路径检查，不因没有具象对象而判失败。

## 5. 系列视觉合同

默认读取 `design_tokens.json`，不要在单页脚本中另建相互冲突的色板。

- 画布：纯白；内部浅色对象与画布之间必须有表面色或清楚边框。
- 强调色：按 `design_tokens.json` 的本期配色政策和跨页颜色职责表，使用和谐的低饱和主色、辅色。文件中的通用 `colors` 仅作回退值；色相及各自表达的信息角色由本期内容决定，跨页保持一致。不得把其他节目的蓝赭配色或颜色含义当成固定模板。
- 模块标题：字号大于正文，入口统一且易扫描；编号只负责导航。
- 页眉页脚、来源和页码：遵守系列合同，不显示版本号、内部 ID 或流程状态。
- 页眉页脚和页边距的数值只读取 `rules/page_visual_production.md` 第 4.1 节与 `design_tokens.json`；Deep Dive 不另设一套边界坐标。
- 页面只使用原生 Excalidraw 元素；正式 scene 的 `image` 元素必须为 0，`files` 必须为空。PNG 只能由当前 scene 导出，不得作为嵌入素材回填 scene。

继承旧 scene 时，在最终 scene 上统计并归一化所有 `strokeColor` 与 `backgroundColor`；只修改新建元素不能证明旧颜色已经消失。

## 6. 构建前自检与送审

创作者只能拦截明显问题，不能判定通过。送审前至少确认：

- 所有重要内容在画面中真实可见，不只存在于 metadata；
- 实际绘制的关键对象有可见依据，必要短标签可帮助识别；图文合起来比纯文字更清楚地解释关系，文字主导区域的主次、关系和证据仍可扫描；
- 从真实 PNG 沿主阅读路径逐区复述：前一区域为何引出后一区域，后一区域怎样推进本页结论；并列区域有共同问题，不被画成错误因果；
- 每条连接线有明确起点、关系和终点；
- 所有可见编号、数值、引语和案例标识有来源；
- 当前 PNG 来自当前 editable scene；
- 无裁切、压线、穿字、碰撞和画布外元素。
- 原尺寸 PNG 与 390px 整页预览都已实际打开；主结论、证据正文、事实限定和边界在手机预览中无须放大即可辨读。微型标签失败时删除或提升其内容职责，不得继续缩字。
- 在原图量出核心结论末行至正文首个可见对象、正文末行至页脚分隔线的空隙；结合阅读分组和同系列已通过页判断留白是否有职责。若上下空隙挤占正文容量，先重排正文内部与对象尺度，再检查手机阅读；不靠缩字或移动已固定的页脚合同填空。
- 联合预检中记录的 `taste.md` 原则已在当前 PNG 上产生可见证据；不得只写在文档中。
- 所有页标题、模块标题和总结句的来源强度已单独复核；`case_inference` 保留人物、时间或案例限定。
- 每个可见容器都通过边框语义检查；页面没有依赖框框套框维持秩序。
- 任何删图、减文、重组栏位或简化核心对象的返工，都已将新 PNG 的可见内容与 Page Content Pack 重新逐项对照；支撑细节、问句、案例、条件和边界没有因为“画面更干净”而消失。
- 每个关键文字块和图形都能指出其语义归属；案例专属问题没有因位置落到另一案例或共同结论轨道。
- 并列／主次关系已经同时检查面积、标题等级、对象尺度、视觉墨量、细节量和阅读时长；画面权重与论证权重一致。
- 核心局部图已通过“整体对象优先”检查；若局部连同必要短标签仍不能确认所属对象，画面先提供完整对象或来源支持的场景。
- 核心对象已通过“装配连续性”检查：安装面、接触点、作用方向和对应部件可见；图形状态与动作／结果文案一致。

### 真实渲染文字间距门禁

对当前原尺寸 PNG 执行一次逐区文字间距检查：

1. 标题先按真实可用宽度判断是否需要换行；若一行可以舒展排下，不沿用上一页或旧版本的固定行数。
2. 每个长句逐项检查与容器边框、分隔线、箭头及相邻文字的实际可见间距；文字不得触线、穿线或依靠裁切隐藏末字。
3. scene 的文本 `width`、元素未越界、JSON 可解析和静态碰撞检查只作辅助，不能替代 PNG 观察。
4. 发现一处裁字、压线或不必要换行后，横向检查全页同类文本；不能只修用户点名的位置。
5. 标题行数、字号或行高改变后，重新计算副标题、页眉分隔线、场景标题和正文起点，再检查原图与 390px 预览。
6. 存在多栏、容器或明确文字轨道时，在临时诊断副本上标出栏界，检查真实字形是否跨栏；诊断线不进入正式 scene。有限栏宽内的中文长句优先显式换行。
7. 恢复内容后若手机字号不足，先重新分配宽度、拆分文字组或改变空间层级；不得通过删除事实或缩小关键正文来维持布局。
8. 除整页观察外，放大检查每个“末字×竖线”“标签×箭头”“页脚×底边”交点；用户截图指出可见接触时，既有静态检查与独立审核结论立即失效。

满足后状态只能是 `submitted_for_independent_review`。

正式送审前，在当前页目录保存 `RENDERED_PAGE_CHECK.md`，且必须绑定当前 PNG 哈希。文件至少包含四张表：

1. **规则→像素：** 预检关键原则，当前 PNG 可见证据，结果；
2. **图文解释与线条：** 对象图记录可见线索、必要文字及两者相对纯文字的解释增益；文字主导区域记录主次、关系和证据；所有显眼线条记录职责与结果；
3. **内容差异：** Page Content Pack 必留项，当前可见位置，边界是否保留，结果；
4. **文字几何：** 栏界、长句、容器、箭头、390px 关键正文和同类问题横向检查。

任一表格存在 `fail`、`unknown` 或无法指向真实 PNG 位置的行，页面不得送审。该文件用于创作者自我拦截；隔离审核者不读取其结论，仍从原尺寸 PNG 独立审查。

## 7. 隔离审核与返工

独立审核者只读查看当前原尺寸 PNG、Page Content Pack、正反案例、同系列已通过页面和质量规则，不读取创作者自评或返工投入。

- `REJECT-A`：主视觉廉价、机制缺失、对象错误、来源不忠或构图模板化；返回视觉假设，通常重建核心 scene。
- `REJECT-B`：整洁但图形解释价值不足；在用户授权的两轮返工上限内返回视觉解释方案，到达上限后停止重复制作；是否展示限质结果按 visual_pack_execution 的明确授权执行，不自动取消 TARGET 展示门槛。
- `TARGET`：只表示可提交用户，不代表通过。

按最早失败层返工。结构失败不能用颜色或字号补救；局部文字、配色、背景和间距调整后，也必须重新渲染并重新隔离审核。

## 8. 用户通过与下一页

默认三案选图按 `visual_pack_execution.md` 的选择状态推进：所选TARGET走正式用户验收；合格B案被用户选定后记 `selected_for_progress_quality_pending`，可继续但不写正式accepted。本节以下正式通过步骤适用于单案逐页确认或三案所选TARGET；用户明确授权批量完成时按visual_pack_execution记录逐页审核及待验收状态，最终一次交付，不逐页重复询问。要求先调整一页时保持单页范围，通过后才迁移。

用户明确通过后：

1. 保存 accepted PNG 与 `.excalidraw` 的哈希；
2. 写入 `page_human_approval`；
3. 将 page gate 改为 `accepted`；
4. 记录本页新增的可泛化规则与仅适用于本页的设计；
5. 默认逐页模式下才开始下一张 Deep Dive。用户已明确授权限质输出后继续逐页制作时，执行 `rules/page_visual_production.md` 的例外：下一页可开始，但前页仍记录为 `REJECT-B` 限质；用户另行接受该限质版时按 `visual_pack_execution.md` 记录，不写正式质量 accepted 或正式发布通过。

人工通过绑定具体 scene 与 PNG 哈希。若用户后来基于新的可见证据重新打开该页，旧通过记录保留为历史基线，当前候选退回 `needs_revision`；修复后重新真实渲染、重新隔离审核并重新请求用户确认。旧审核报告和旧通过哈希不得晋升新版本。
