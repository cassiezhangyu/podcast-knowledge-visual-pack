# 独立视觉审核协议

本协议用于 Cover、Overview 与每张 Deep Dive 的成图审核。创作者和视觉审核者必须隔离；两者不能由同一执行上下文连续担任。

## 1. 角色边界

### 创作者

- 读取已通过的内容产物和页面合同，提出视觉方案并构建可编辑 scene。
- 负责真实渲染、机械预检、内容来源映射和明显缺陷修复。
- 可以记录设计意图和自检结果，但不得给出 `TARGET`、视觉通过或可交付结论。
- 正式提交审核时状态只能是 `submitted_for_independent_review`。

### 独立审核者

- 使用与创作者隔离的上下文，只读检查当前原尺寸 PNG、Page Content Pack、正面参考、负面标准和固定系列规范。
- 不读取创作者的候选偏好、投入成本、自评分、相对改进说明或“希望通过”的结论，避免锚定。
- 不修改 scene、不代替创作者修图，只输出可见证据、分类、失败层级和最小返工方向。
- 只有独立审核者可以在内部预审中给出 `TARGET`；用户仍拥有最终通过权。

首读当前原图与390px时，先记录实际阅读入口顺序、各入口标题与同级组、最强与最弱信息区域，再读取scene角色标签和作者提供的编号映射核对。编号按模块合同一一定位，同级标题按职责比较字号与字重；角色标签合法不能抵消职责错标，重复编号不能以“主题返回”豁免。先完成这组独立观察，再判关系收益与整页审美，并一次汇总当前全页缺口；不得只围绕上次修复点复核。

若当前环境无法提供隔离审核，页面保持 `independent_review_required`，不得由创作者自审后晋升。

### 完整构建前的独立原型读回

新页面或主结构改变时按visual_reasoning第3–4节先审核实际原型：先从当前PNG读回对象、比较或变化与判断依据，再读内容、参考和规范核实；逐案指出可见依据、来源误读与解释缺口，并并排判断三案的主解释方法是否充分不同。原型报告用 prototype_pass 和 core_explanation_sufficient 分别记录原型准入与核心充分性，并给 visual_gain_counterproof 的 simple_alternative、remove_subject 实图证据；另按 visual_reasoning 第4节独立记录 full_build_ready 与 full_build_readiness_evidence 的三个字段。三案并排后再给 three_methods_passed。核心充分不自动表示值得完整精修，两项判断可以不同；不判 TARGET。绑定创作者/审核者上下文、当前scene/原图/390px/灰度和所读输入哈希，不读取作者意图或自评。

prototype 检查同时要求核心充分、完整构建准备度及整页构图通过和对应证据。CLI与既有字段保留；新prototype/page/selection准入报告扩展构图证据，缺字段的旧报告不自动补true。历史完整等级、用户验收和返工计数保持原适用范围；旧工件要重新进入当前放行时，按当前规则只读实图重新审核。

scripts/check_visual_progression.py 以 --stage prototype、page 或 selection 和 --report 报告路径接受原型、批量放行或三案展示检查。prototype/page 内部单案验证可加 --case A（或 B/C），不取消最终三案方法审核。selection 读取 stage=page 的当前三案完整报告，要求方法成立、至少一案 TARGET、其余至少 B；page 三案批量放行仍要求全部 TARGET。每案包含 case、current 四类工件绑定、readback 和 visible_evidence；用于 selection 的完整报告每案还须写 blocking_errors，只有空数组 [] 才表示审核者确认内容、来源、几何和手机阅读无阻断，缺失不能自动视为无错误；TARGET 案另写 explanatory_gain 与 reference_comparison 的实际证据；原型用prototype_pass，完整图用grade；报告包含stage、page_id、creator_context_id、reviewer_context_id、inputs绑定清单、three_methods_passed及method_evidence。脚本只验证记录和当前文件，不证明审美。报告不能以图形可识别、能复述一个抽象关系替代决定性关系已充分解释；按visual_reasoning的简洁图文反证检查解释收益与正常字级整页容量。完整页仍重新审核，原型PASS不继承为TARGET。

### 原型与完整质量分别判断

原型按 visual_reasoning 第4节检查当前来源中的决定性关系是否准确、可读并完成本页任务。条件、分类或范围可以只需一层；“没有更多机制”不能独自证明不充分。比较基线是同样事实的线性文字或基本段落分组；若替代已含同一有效图形组织，不再要求额外复杂度。准确关系仍可因尺度失衡、空载体、绘制粗糙而被拒，须定位实际失败层。

完整 TARGET 另外检查实际正例下的审美完成度：焦点和阅读节奏、密度与可细读局部、绘制可信度、图文贴合、手机体验。不得仅因原型关系正确就升级；也不得把审美差距一律归为来源不足。报告指出最强成立关系和最强未解决缺口，不能只说“仍靠文字”。

主区与支撑区分别检查，信息权重不同不降低完整审美要求。来源已有具体例子、对象、转向或比较，而支撑区仍以多段连续文字为主、缺少内容驱动的视觉组织时，按完整审美不足判 REJECT-B；不能以“支撑区分量合适”“主要图已成立”或“手机可读”豁免后签 TARGET。指出实际区域、可组织的来源材料与读者仍须逐段完成的工作。必要解释和来源限定可以保留正文；不强迫每段配图。装饰图标、文字换框、换色或分隔线不能代替改进证据。用户明确否定这项不足后，旧 TARGET 只保留原版本历史，按最新反馈重新审查当前图。

三案差异按 visual_reasoning 第6节分别审查解释方法与宏观构图；three_methods_passed 保留为兼容字段，不要求为同一事实补造三种机制。每案原型与完整报告另需 composition_passed、composition_evidence 四项文本及 series_repetition_check；三案另需 composition_diversity_passed 与 composition_comparison。先看实际缩略图分布，再细读，指认主体／支撑位置、证据组织、密度与路径；同一横带骨架内换物件或方法不能代签构图通过。旧报告缺少新证据时保留历史，不补签、不外推到当前放行。字段和具体准入条件统一见 visual_reasoning 第4/6节，脚本只核记录完整与哈希，不判断空间质量。

## 2. 审核输入

### 已验收冻结工件重新审核

补齐已验收页面的当前正式记录时，使用 prepare 的 `--revalidate-existing --prior-approval <原始用户验收.json> --gray <当前灰度.png>`。原始验收须明确通过并精确绑定当前 scene、原图、390px、灰度四哈希。保存本次复核前的输入检查，状态为 `completed_before_existing_artwork_review`，绑定当前内容、规范与真实正反参考；该记录早于本次成图自检，明确它是冻结工件复核，不声称历史创作前预检。图片改变后此入口拒绝，改动版本回到正常生产与新验收流程。完整隔离审核、TARGET 和用户验收要求保持不变。

prepare 将颜色职责表保存为独立 JSON，并在审核包 standards 中绑定路径与文件哈希；审核者读取该文件，closeout 核验相同文件。默认新创作入口仍要求预检早于 scene，不使用冻结复核分支补签历史记录。

正式送审前由创作者运行 `npm run visual:review:prepare` 生成只读输入包；命令和参数见 `SKILL.md` Phase 8。命令核对构图前 `REFERENCE_PREFLIGHT.json` 与当前内容、正反案例、`taste.md`、`design_tokens.json` 的哈希和文件时间，并要求当前 scene/PNG 绑定的 `RENDERED_PAGE_CHECK.json` 五项均通过；然后绑定创作任务 ID、scene、原图、390px 图及规范的哈希，自动拒绝含位图的 scene。审核者只接收该包并自行打开每个文件；包内保留预检与自检哈希及本期颜色职责表，不传入创作者的案例观察、构图方案和自评。审核报告必须记录审核任务 ID，closeout 拒绝与创作任务 ID 相同的审核上下文。

必须提供：

- 当前原尺寸 PNG；
- 当前页 Page Content Pack；
- 已获用户通过的同系列正面页面；
- `taste.md`、`rules/design_gates.md`；
- 固定页眉页脚、画布和本期颜色职责表；审核者对照真实页面检查颜色是否按职责使用，并确认必要证据与边界没有被弱化。
- 创作者在构图前实际查看的正反案例清单及文件哈希；审核者需自行打开这些图片核验，不能只信预检结论。

默认不提供：创作者的视觉方案说明、版本修正过程、自检结论和机械通过摘要。只有定位技术问题时才补充，并在报告中标记新增信息。

若用户质疑旧版拒绝结论，争议重审额外提供用户原话、被比较版本的原尺寸 PNG 与 390px 预览、旧拒绝报告及其具体理由。审核者自行对照这些阅读证据；不接收创作者对版本优劣的自评。

### Cover 专属输入与隔离检查

审核 Cover 时，以 `rules/cover_page_production.md` 取代 Page Content Pack 的页面专属结构，并额外读取：

- `COVER_BRIEF.md`；
- 原节目元数据及已通过《内容拆分》的整期主命题；
- 当前封面 scene、原尺寸 PNG 与 390px 预览；
- 官方专辑图原文件与哈希（若使用）；
- `examples/positive/e248-cover-accepted-2026-09-22/`，只作为完成度与视觉语言校准。

审核者先独立写出从封面读到的“节目身份、整期问题、中心图表达的关系”，再查看 Cover Brief。三者不能一致时，按内容／视觉错位拒绝。随后检查：

1. 原节目标题是否准确、完整并为第一视觉层级；
2. 编辑钩子是否覆盖整期，而不是放大局部案例或改写成耸动问题；
3. 中心知识图是否用对象、动作或状态解释钩子，删除后是否造成实质理解损失；
4. 是否只有一个主要视觉锚点，且未使用全页蒙版、Overview 透影、拉长背景或抽象线条填空；
5. 节目名、官方专辑图、关键词、节目形态标签、人物和时长是否各司其职；
6. 期号是否重复或抢占标题层级；
7. scene 是否保持 `image=0`、`files=0`，官方专辑图是否仅作为有哈希的最终品牌合成层；
8. 原图与 390px 下标题、钩子、中心结论、关键词和出场信息是否都能辨认。
9. 彩色文字、中心图、中心底板和弱分隔线是否来自本期声明的一个主色与一个辅色，并保持语义一致；背景不能成为孤立的第三种主题色。不得因 E248 正例使用蓝赭，就要求新播客也使用蓝赭。

不得因沿用了正面案例的具体对象、坐标或版式而给分；换一期内容仍可原样成立的中心图按模板化拒绝。

## 3. 高质量标准

审核者必须以可交付成图为标准，不以“比上一版好”“内容都在”“没有越界”或“已经可编辑”为标准。先从实际图固化核心解释的质量判断，再核对来源与规范；规范或机械合格不能补偿解释不足。报告使用现有 readback、visible_evidence 和判级理由，说明读者比较的具体差异、由此形成的主要判断、相对简洁图文的实质收益，以及当前最强不足。判 TARGET 时还须对照实际正例的相关局部，指出解释深度、信息密度与图文协同如何达到标准；“有空间关系”“不像文字框”“符合画风”不是充分理由。只解释了一层概括含义且占据主体大面积时，检查是否仍为 REJECT-B，不替作品补写画面里看不见的推理。逐项检查：

1. **首屏理解**：5 秒能否发现页面问题、主解释结构和关键转折。
2. **解释价值与可见关系**：看页面采用具体图像、逻辑关系、文字结构或其组合之后，是否比纯文字逐段阅读更清楚、生动地讲明本页问题。先复述从成图读到的整页答案，再对照 Page Content Pack，逐项指出其中决定性关系对应的可见对象、状态或空间依据，以及必要文字如何补足准确含义、证据与边界；不要求遮字后图独自讲完关系。辅助案例的绘制完成度须与整页核心关系的覆盖分开判断。若图形只重复文字、画错关系，或整页仅靠长句、抽象标签、箭头与导航编号维持解释，构图不合格。
3. **内容充分**：重要案例、机制和边界是否真实可见，而非只存在于 metadata 或小字中。
4. **内容专属**：换成另一篇文章后，当前构图是否失效；三段流程、卡片宫格、中心词加分支等通用模板不得通过。
5. **图形完成度**：人物、物件和动作可识别，简笔画有意图和细节，不以廉价图标或标签抢救弱图形。
6. **图文协同**：图像能降低理解成本时让图像承担相应解释，文字负责需要准确表述的论点、证据、条件和边界；无法不失真地画成实物时，允许文字与逻辑关系主导。两者不得只重复同一句话。
7. **视觉层级与密度**：主次、阅读路径和局部细读成立；大面积空白、大图低信息、小字堆积均视为失败证据。
8. **系列一致性与模块合同**：页眉页脚、字体尺度、颜色语义和整体完成度不低于用户已通过的正面页面；按当前合同实际检查整包地图、本页提纲、正文对应序号、完整单集标题、回听与独立页码。明确锁定的几何保留，未锁定或已授权可变的位置按内容适配核验；默认示例不构成右栏要求。缺少职责、地图页段过期或提纲无法定位正文时不得通过。
9. **原尺寸可读性**：正文、注释和边界在原尺寸清楚，无裁切、压线、碰撞和依赖放大的关键内容。
10. **来源安全**：逐项检查可见编号、数值、引语、产品名和案例标识是否来自 Page Content Pack；为追踪图形而自造、却看似属于原节目或产品的标识直接拒绝。
11. **原生工件**：检查 `.excalidraw` 中 `image=0`、`files=0`，当前 PNG 来自同一 scene。发现任何嵌入位图直接拒绝。
12. **手机阅读**：实际查看 390px 整页预览；主结论、关键证据、事实限定和内容边界需无须放大即可辨读。分别指出哪一行难读及其论证职责，不用估算字号或辅助来源较小替代真实阅读判断；允许用户明确接受的略小但仍可辨文字。
13. **来源强度**：先审页标题、模块标题和总结句，再审正文；检查个案解释是否保留人物、时间、条件和范围，是否把“仍然如此”扩大成“完全没有改变”，或把一个案例写成普遍标准。
14. **边框语义**：检查每个描边容器是否表达真实对象、对象状态或约束边界。大量只为排版而存在的等权圆角框、嵌套卡片和文字装盒属于结构失败；开放构图则必须仍有清楚的阅读顺序和模块边界。
15. **渲染文字几何**：按当前原尺寸 PNG 逐区检查标题断行、长句末字、文字与边框／分隔线／箭头的可见间距；特别逐一查看右栏、浅底区域和页脚。报告写明高风险文字的元素 ID 或准确句子、所属区域及实际可见间距，不接受笼统的“没有越界”。scene `width`、off-canvas、JSON 或静态碰撞通过不能抵消真实 PNG 中的裁字、压线和贴边；发现一处后横向检查全页同类文字。
16. **规则到像素**：将创作者预检中声明采用或拒绝的关键规则与当前 PNG 逐项对照。“已读规范”不是证据；若预检声称禁止抽象线条或微字，画面却仍出现，直接拒绝。
17. **对象识别与线条职责**：对实际绘制的物件或动作图，暂时忽略标签，确认对象、接触点、改变部件和状态仍可识别；文字型逻辑结构则检查关系是否准确、节点是否有实质内容和阅读方向是否明确。每条显眼线条必须可归为对象轮廓、真实部件、已授权的关系连接、分隔或基线；需靠标签才能猜出的弧线、自由轮廓或箭头按结构失败处理。信息框、导航边界和长分隔线应在原尺寸读作有笔触的单线；沿整段可追出的平行双线不以“手绘感”放行，具体物件允许局部自然复描。
18. **修复后内容差异**：若候选页经历删图、减文、重组栏位或简化核心对象，将当前 PNG 的可见内容与 Page Content Pack 重新逐项对照。支撑细节、问句、案例、条件或边界任一遗漏，即使画面更整洁也不得通过。
19. **栏界与文字轨道**：多栏、容器或并排文字存在时，在临时诊断副本上标出实际栏界，以真实字形检查跨栏、贴边与相互侵入。诊断线不进入正式 scene。显式换行、重分区域或扩展宽度优先于缩小关键正文。
20. **语义归属**：逐项判断专属事实、解释、追问和边界在视觉上属于哪个案例或对象。文字提到正确对象不能抵消错误空间位置；只有共同结论可以进入共同轨道。
21. **论证权重**：比较各主要区域的面积、标题等级、对象尺度、视觉墨量、细节量和预计阅读时长。指出主要视觉分量是否覆盖整页决定性关系，辅助案例是否获得与其论证职责不相称的视觉分量；案例本身承担决定性论证时，可获得相应权重。画面形成的主次必须与 Page Content Pack 一致；等权与主次都要由内容证明，不设统一主图面积配额。
22. **整体对象优先**：局部结构或放大图若承担关键解释，确认页面先建立了可识别的完整对象、使用场景或足够整体形态。遮去名称后只剩无归属零件时，按对象识别失败处理。
23. **装配连续性与状态一致性**：关键部件是否具有可见安装面、接触点、作用方向和对应对象；组合后是否仍像真实对象而非悬浮图标或通用符号。对象位置、部件状态、动作说明和结果文字若不处于同一明确状态，按机制错误处理。
24. **页面边界几何**：在原尺寸 PNG 上记录顶部首可见像素、底部末可见像素、最靠右关键文字像素，以及高风险文字到相邻线条的最小可见间隔。1200 × 1600 内页按当前系列合同检查 x=80 / x=1120、安全区内缓冲、上下外留白差和 22px 页眉页脚。只说“看起来有留白”或引用 scene 坐标不能通过。
25. **局部交点放大检查**：逐个放大“末字×竖线”“标签×箭头”“页脚×底边”等交点；全页缩略图没有明显碰撞不能替代局部检查。用户提供的可见截图证据优先于已有 `TARGET`，必须重开审核。
26. **阅读拓扑、页内关系与页间推演**：先独立写出你从标题进入后的实际阅读顺序，再与 Page Content Pack 和预检声明比较。每读完一个主要区域，除指出下一处位置，还要说清为什么转入它：例证、推进、条件、并列或对照必须有内容依据。只有编号和位置连续，却突然换主题，按语义断链处理。连续 Overview 须同时看相邻两页，复述前页留下的问题如何引出后页，以及后页怎样推进解释；只有页码或“继续看案例”而没有明确关系，不能算跨页衔接成立。若需要在横向与纵向路线之间猜测，或依赖补丁式箭头才能前进，按结构失败处理。
26a. **Overview 节目级主位**：先只看一张完整原图和 390px 图，固化整期问题、主要知识或核心判断、关系、必要依据、重要应用及边界的复述，再对照全文核心覆盖与页面内容包。指出哪些判断实际可读、哪些只剩话题名、问题或导航、哪些须由其他页面补齐；依赖另一张图才成立的全文核心复述不得通过。续页必要性按 `rules/overview_page_production.md` 检查，不以具体证据或案例展开作为续页成立理由。随后遮去最大案例定位依赖：区分案例细节与整期框架，恢复完整图后判断缺口是局部归属问题还是全文核心缺失；单凭遮挡结果不要求重构。具体知识的展开深度按 Deep Dive 职责审核。
27. **数量语义**：逐项检查紧邻比例、次数、数量和时间数字的可清点图形。方格、点、进度段、人物或重复对象表达出的数量必须与来源数学一致；文字正确但图形给出另一数值时，按图形语义错误直接拒绝。
28. **删除分隔后的局部重审**：若返工删除了竖线、边框、书脊或栏界，不只确认穿字消失；重新写出该区域内部的实际阅读顺序。两组窄栏若失去对应依据、层级交叉或需要猜测左右关系，按局部结构失败处理。

审核必须继承用户已明确确认的视觉偏好。用户已经拒绝的人物场景、儿童画式简笔人物或位图路线，不得被审核者重新列为通过条件。来源不支持具体场景时，审核图文分工和信息载体是否准确；高质量文字型知识图可以通过，纯文字本身不是拒绝理由。仍须拒绝等权文字框、无证据的标签和依赖微字的文章排版。

用户指出被拒版本比后续版本更清楚、或认为某版接近通过时，将该反馈作为新的阅读证据重开审查：对照原图与手机图，逐项区分来源／关系／几何硬错误和可争议的审美判断。不得只复述旧分类或以审核身份否定用户看到的优点；也不得因用户喜欢风格而放过明确的内容失真。结论须说明保留哪些有效关系、最小可修问题在哪里、为何需要或不需要重构。

审查空间隐喻的潜在误读时，先指出它实际增加的可见理解，再给出支持误读判断的具体画面位置与来源对照。若只能提出一种可能读法，却无法指出画面怎样形成该读法，先记为待验证歧义；结合邻近文字与可得的初读反馈复核，不直接判成来源硬错误。若包含、连接或位置已经明确造成错误归属，即使别处有文字纠正，也须记录该风险并判断能否局部修复。

以下情况无需综合打分，直接拒绝：随意大笔一挥的线条承担主要动作或关系；未完成的火柴人、手势或物体充当主视觉；粗糙箭头、星芒和波浪线被用来制造“手绘感”；关键图形连同必要短标签仍无法辨认对象或状态，或图文结合仍没有解释增益；预检声明拒绝的失败模式仍出现在当前 PNG；出现未标明为示意的无来源编号、数值、引语或案例标识；醒目标题把个案推成普遍规律或使用强于来源的绝对措辞。

## 4. 分类

- `REJECT-A`：明显结构失败、模板化、廉价主视觉、图形错误或内容关系错误。确认全局结构失败后，返回视觉假设，从空白 scene 重建。
- `REJECT-B`：整洁但主要是文章排版、流程标签或装饰插图，解释价值和完成度不足。确认全局解释失败后，返回视觉解释方案，通常从空白 scene 重建；达到用户授权的返工上限时停止重复制作，按 visual_pack_execution 的展示授权分别报告阻断或限质结果，保留独立判级，不改判为 `TARGET`。
- `TARGET`：达到当前同系列可交付候选标准，可以提交用户最终审核。

若用户随后提出被拒版更清楚或接近通过，按第 3 节以新增阅读证据重审，再确定返工路线。旧拒绝仍阻止该版作为 TARGET / accepted 正式交付；满足用户授权及两轮上限条件的 REJECT-B，可按 `visual_pack_execution.md` 的限质入口独立审核并明确标注后展示。其返工建议不自动约束重审；确有全局失败时重构，只有可隔离的问题时按页面协议进入 `SCOPED_REPAIR`。用户反馈也不自动将页面改判为 `TARGET`，来源、关系和可读性要求仍须通过。

任何一项核心标准失败都不能以其他项目平均分补偿。审核报告必须引用页面上的可见对象和位置说明理由。

## 5. 返工循环

1. 创作者提交 PNG 与 scene，状态为 `submitted_for_independent_review`。
2. 独立审核者输出 `INDEPENDENT_VISUAL_REVIEW_V*.md/json`。
3. `REJECT-A/B`：创作者按最早失败层返工；新版本重新进入新的隔离审核。
4. `TARGET`：报告逐页记录当前审核输入包的文件 SHA-256；以 `visual:closeout --packet <审核输入包> --action submit` 登记，命令核对报告、审核包、当前 scene/PNG 和参考输入；页面状态仍为 `needs_human_review`，不能自动写入用户批准。
5. 用户明确通过当前 scene/PNG 后，才用同一报告与审核包执行 `visual:closeout --action approve --user-approved`，记录人工批准并将页面状态改为 `accepted`。

用户明确纠正内部评级时，保留旧独立报告及其工件绑定，另记录用户实看证据、当前质量缺口和返工范围；重开受影响的推进结论。旧报告的哈希校验通过不能抵消新增的阅读证据，也不能继续作为扩产依据。相关样本按新证据校准，未实看页面不自动追溯改判。

用户通过只绑定当时的 scene 与 PNG 哈希。若用户后来提出新的可见缺陷，当前页重新进入返工循环；旧通过保留为历史记录，不得替代新版本的隔离审核和人工确认。

独立审核不能继承用户最终通过权，也不能把机械检查当作视觉证据。

## 6. `SCOPED_REPAIR` 独立差异审核

当页面协议确认可进行局部修订时，审核者除第 2 节输入外，还必须读取：

- 用户要求保留什么、只修改什么的原话；
- 基线 scene、原尺寸 PNG 与 390px 预览，以及各自哈希；若基线曾被拒绝，还须提供旧拒绝报告；
- 当前 scene 与原尺寸 PNG，以及各自哈希；
- 允许修改、增加、删除的元素 ID 和允许变化的像素区域；
- scene 差异校验结果。

审核顺序：

1. 确认改动区确实解决用户指出的内容或视觉问题；
2. 对照 Page Content Pack，检查改写没有制造新的因果、顺序、普遍规律或信息缺失；
3. 对比整页 PNG，检查允许区域之外的位移、字号、颜色、遮挡、阅读拓扑和视觉权重回归；
4. 重跑手机阅读和页面边界检查；
5. 给出限定范围的 `PASS`／`FAIL` 与回归证据，并绑定当前 scene/PNG 哈希；不产生整页 TARGET，旧整体等级仅保留为其原版历史信息。

差异审核尊重用户已明确保留的整页选择，不重新把个人偏好包装成返工要求。只有新证据显示基线存在关键内容错误、来源风险、技术损坏或改动引发全局结构回归时，才可重开已认可区域；报告必须指出具体可见证据。scene 校验通过只说明允许元素之外的序列化数据未变，不能替代像素与语义判断。

字号审核必须核对 `typography_hierarchy.md`：缺失 typography_role、字号不等于角色值、同一句跨行或同组并列使用不同角色均退回文字层级修复。机器通过后仍检查真图几何与390px可读性。

## 精修审查范围

审核全包字体时先独立选出每页整页答案、定位说明、模块标题、正文与边界，再核对typography_role与字号；不能只读取创作者角色台账或根据坐标判句子职责。案例反证、侧论或应用不覆盖主问题时不能承担整页核心。随后实际看改动页的原图与手机图，定位断行、孤立标点、压线和页脚挤压。笔触精修实际比较对象与排版线的区别，不能只比较roughness。

报告注明完整页面审查还是限定修订范围审查。后者记录该范围的通过/未通过及当前hash，不产生整页TARGET判级；旧整体等级保持为其原版本的历史信息。连续批量模式仍须逐页实际审查，样稿或部分页通过不代替其他页。

## 授权限质审核入口

三案选择模式的 `REJECT-B` **候选判级**先按 `visual_pack_execution.md` 第 4 节执行：审核者独立打开该案的当前原图、390px、灰度图、scene、完整内容包、正反案例与当前规范，报告当前文件哈希、可见缺点和 `TARGET`／`REJECT-A`／`REJECT-B`。若内容或来源有误、文字遮挡或手机不可读，应判为不具备选择资格，不以整体整洁度抵消。该报告只供用户比较三种设计，不是下文两轮返工后的限质发布审核，也不生成正式 closeout 通过记录。

正式审核的五项 pass 和 closeout 要求保持不变。用户已授权两轮上限、候选仅在视觉解释或案例完成度未达标时，按 `visual_pack_execution.md` 第 5 节建立 `limited_review_input.json`，交隔离只读审核者实看当前图片。该输入不是正式审核包，不改写自检失败，不调用正式 prepare / closeout，也不自动赋予 accepted 或 RELEASED。
