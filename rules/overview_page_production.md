# Overview 页面生产协议

本协议规定节目级总览页如何守住内容、建立关系和选择返工范围。内页模块执行 `rules/inner_page_module_contract.md`；正文不固定模块数量、栏数、时间线、颜色、工作台或图形构图。通用逐页流程仍执行 `rules/page_visual_production.md`，成图审核仍执行 `rules/independent_visual_review.md`。

## 1. 页面职责

Overview 用一张完整图汇总全文核心内容并建立节目级理解框架。首次接触者不依赖音频、伴读文案或另一页，正常读完该图后应能复述以下内容；已经了解节目的人可在 20–30 秒内用它恢复 whole picture：

- 节目在回答什么核心问题；
- 节目给出的主命题是什么，以及不能被误解成什么；
- 主要知识或核心观点具体是什么，而不只知道话题名称；
- 核心观点依靠什么关系、解释或必要依据形成整体框架；
- 各部分是怎样的关系，哪些只是并列、补充或独立反思；
- 结论在什么条件和边界内成立。

页面保留建立框架所必需的概括、关系和必要依据；案例、论据、完整机制与主题专属边界交由 Deep Dive 展开。某个案例若本身就是核心观点或理解框架不可缺的依据，保留其作用与最少可读信息。按 `rules/page_content_planning.md` 第 0 节逐项核对全文核心覆盖和细节去向；任何省略都须有内容理由，不能让独立主张只剩导航名称。

### 单页容量与续页必要性

先验证单张总览的完整核心框架。容量紧张时，先核对内容职责，移出重复叙述和应由深度页展开的材料，再重组关系与视觉权重，保留正文级可读文字。只因需要更多案例、论据或详细边界，就增加一张总览，属于职责错分。

只有**核心框架本身**在真实原图和 390px 图中仍发生可见折损，才提出续页方案：列出无法同时辨读的核心判断或关系、已尝试的单页重组及仍有的具体损失。续页须承担不可互换的节目级框架任务，第一张仍独立覆盖全文核心；把关键判断留到第二张才补齐，不满足一图复述要求。若方案实质是具体知识展开，将它作为深度页规划。用户明确要求单张时，先提交容量冲突与可审的重组方案，保持单张合同，不能擅自增加页数。

保留同一张图的内容完整性、手机可读性与关系准确性，不将空间估算、Coverage 完整或局部原型通过当作整页容量已验证。任何获准续页分别接受真实渲染、隔离审核和用户验收。

拆页候选不得占用已批准 Deep Dive 的页码；通过前保留候选页 ID。全部续页获用户确认后，逐项同步 Editorial Plan、Coverage Matrix、页面清单、导出顺序和后续页码，并检查每个已通过内容单元的去向与重复程度。单页合同不能仅靠额外导出 PNG 视为已经支持多页交付。

获准连续 Overview 时，记录续页补充哪一项节目级框架、为何值得独立存在及两页有来源支持的关系；具体应用、证据和边界的展开优先按深度页职责处理。禁止用连续页码、同色或箭头暗示来源不支持的因果、必经顺序或一一对应。

## 2. 构图前先完成内容骨架

从已通过的内容拆分、Knowledge Graph、Editorial Plan 和 Coverage Matrix 提取以下内容；缺一项不得先画版式：

1. **核心问题**：整期真正要回答的问题。
2. **主命题**：节目最终支持的判断，以及反误读句。
3. **核心观点与关系**：全文主要板块各自的实质判断及其与主命题的关系；有解释链时保留必要连接，来源为并列时如实并列。
4. **必要依据**：只提取建立框架所必需的机制、证据或案例，其具体展开映射到深度页。
5. **扩展与应用**：改变整体理解的独立应用须显出核心判断和归属；次要应用按重要性记录深度页去向。
6. **条件与边界**：框架层必须保留的范围、不确定性或不能推出的结论；主题专属限定随具体知识展开。
7. **可选平行问题线**：见第 4 节；不存在时明确记为“无”，不得为了版面完整强造。

先用一句话说明整页的解释任务，再为以上实际存在的内容分配视觉权重。模块编号只可辅助定位，不能代替关系和主次。

### 整页结论与辅助导航

主标题负责提出或命名整期问题，副标题限定讨论范围，整页核心结论用陈述句说出节目真正支持的判断。结论须能单独读通，并与正文关系拓扑一致：并列角度不能被一句话误写成两两配对或先后步骤，回应、边界也不能被写成前三项的必然结果。不要用“本期讨论的核心问题是……”代替判断，也不要把问句当作结论。结论是正文入口，位置和字级要高于模块标题；若使用标题区分隔线，应放在副标题之后，使结论成为独立层级。

右侧辅助导航按内页模块合同分为**整包内容地图**与**本页提纲**，页码独立放在页脚，分别承担“整期有哪些内容”“本页从哪里读”和“当前在第几页”。地图写内容主题及对应页段；本页提纲与正文使用同一组定位标记。若几项并列、另一项是相关但独立的回应，用分组、括线、间距或说明表达这一差别；连续数字和同色列表本身不足以说明关系。浅底或弱边界用于划清导航与正文，颜色、面积和字号保持辅助权重；正文自身的图形布局仍按内容决定。

### 节目级主位检查

先写单张总览怎样覆盖全文核心观点，再为获准续页写不可互换的框架职责。构图前列出主视觉所占的内容、预计画面面积、其余核心论点与必要依据的可见去向。若局部案例成为最大或最醒目的对象，先看**完整页面**能否让陌生读者说出整期问题、主方法、其他主要判断和边界，以及该案例为什么能解释主命题；有续页时还要说出下一页的职责。

随后遮去最大案例作压力测试，定位整期框架是否只剩空泛口号或目录。遮挡会拿走案例本应承担的解释细节，因此不要求其余区域再完整复制一遍案例中的方法，也不凭遮挡后的复述不全自动判整页失败。先回到完整成图确认读者实际得到的节目级理解：若问题只是案例外的概括、归属或范围不够明确，优先定位局部补强；若整页实质上只能读出局部案例、缺少其他应用和边界，才返回页面职责与画面权重分配。此检查不规定案例比例，也不禁止以一例解释主方法。

## 3. 关系台账：先授权语义，再连接图形

构图前建立 `OVERVIEW_RELATION_LEDGER.md/json` 或等价记录。每一条准备在画面上被读成关系的连接都必须记录：

- `from` 与 `to`：连接的两个内容对象；
- `relation_type`：因果、条件、递进、顺序、对照、并列、例证、扩展、反例或反思；
- `source_ids`：已通过的 relationship、knowledge object、parallel context 或 boundary；
- `directionality`：有方向或无方向；
- `allowed_visual_cues`：允许使用的箭头、路径、邻近、括组、重复形态、颜色连续或其他线索；
- `forbidden_reading`：读者不能由此推出的因果、必然、先后、同一对象或普遍规律。

台账必须覆盖显性箭头，也要覆盖会自然制造关系的视觉线索。连续路径、相同颜色、相同形状、编号顺序、共同容器和空间邻近都可能让读者推断关系，不能以“没有画箭头”为由免审。

当 Overview 有续页时，台账另记录相邻页面的 `from_page`、`to_page`、`relation_type`、来源支持、读者进入后页前应形成的具体问题，以及禁止误读的对应或因果。页间过渡文案和两页标题必须与这条关系一致；两张单页各自清楚不等于整套阅读链清楚。

**视觉连续性不能发明语义连续性。** 若两个内容只是在同一期节目中出现，不能因为排版需要让同一对象在两区之间迁移、让一条路径穿过两区，或用同色同形暗示它们属于同一因果链。关系没有得到台账授权时，使用分区、留白、不同阅读轨道或明确的非因果说明。

## 4. 平行问题线是条件分支，不是必备模块

只有同时满足以下条件，Overview 才可出现独立的平行问题线：

- 节目确实提出了一个区别于主解释链的问题；
- 它有自己的证据或经验材料，而不是一句旁白；
- 它能形成可复述的判断或反思；
- 它有自己的条件、范围或不确定性；
- 强行并入主链会制造错误因果、时间顺序或必然结果。

只满足“主题相关”“同一人物说过”或“适合填补版面”时，不建立平行问题线。若平行线与主链存在启发或联想，只表达有证据的弱关系，并同时给出不得推出的结论。

栏目须呈现实质内容：使用“现场问答”“案例”“延伸讨论”等名称时，交代来源支持的具体对象；属于全文核心的独立应用，还须让读者复述其中的主要判断，只有问题清单或话题名不算完成。能共享判断的条目可以概括，具有不同答案的条目保留区别，并说明与主线的并列、应用或弱关联。数量由全文核心覆盖与 390px 容量决定，次要条目记录深度页去向；现场回答保留个人经验属性与适用边界。

## 5. 节点角色不能被版式抹平

进入 Overview 的内容至少区分以下角色：事实/经历、机制、成立条件、外部影响、解释或反思、边界。它们不能仅因排在同一横线、使用同样节点或编号连续，就被画成同等步骤。

- 事实和经历回答“发生过什么”；
- 机制回答“怎样导致或支持结论”；
- 条件回答“在什么情况下成立”；
- 外部影响回答“什么参与了变化”，不自动等于原因；
- 解释或反思回答“人怎样理解这些材料”，不倒写成当时的动机；
- 边界回答“不能推出什么”。

视觉权重、位置、连接方式和文字语气应共同保持这些角色差异。

## 6. 陌生读者复述门禁

在草图或核心原型阶段，让一个未参与内容生产的读者或隔离审核上下文先只看该页，复述核心问题、主命题、主要判断与关系、必要依据、重要应用和边界；固化首读后再对照全文核心覆盖表。真实完整成图以原尺寸与 390px 重做该检查，原型首读不能代替成图复述。

通过条件：

- 复述出的关系与关系台账一致；
- 未把并列读成因果、把反思读成事实、把个案读成公式；
- 能说清各主要板块的实质判断与主次；全文核心覆盖表中没有只靠另一页、音频或创作者说明才能补出的核心观点；
- 页面不存在的可选结构不作为缺项。
- 获准续页时，先验证第一张能独立复述全文核心，再检查续页新增的节目级框架理解；详细证据或案例展开按深度页检查。
- 遮去最大案例后，记录失去的是案例应承载的细节，还是整期框架本身；再恢复完整页面判断读者能否复述主张、主要应用范围与边界。仅凭遮挡结果不作重构结论。

若复述失败，先修内容骨架、关系台账或阅读拓扑，不以增加箭头和编号代替。

## 7. 返工范围判定

### `RECOMPOSE`

以下任一情况需要回到内容骨架或视觉解释方案，通常从空白 scene 重构：核心问题或主命题不成立；主要关系错误；阅读拓扑竞争；主次颠倒；图形隐喻制造了无来源逻辑；多个区域同时依赖错误结构。

### `SCOPED_REPAIR`

只有同时满足以下条件才允许局部修订：

- 用户明确保留当前整页构图、认为当前版接近通过并要求局部精修，或已有认可基线；
- 问题能被定位到一个独立区域、文案或一组稳定元素；
- 修订不改变其他模块的关系、阅读拓扑和视觉权重；
- 基线与候选具有稳定元素 ID，允许改动范围可以列举；
- 改后仍重新渲染整页，并接受独立差异审核和用户确认。

开始前冻结基线 scene/PNG 哈希，列出允许修改、增加或删除的元素与像素区域。scene 级校验使用 `scripts/verify-scoped-visual-repair.mjs`；它只能证明允许范围外的 scene 元素未变，不能替代真实 PNG、内容审核或视觉审核。

若局部修订造成跨区位移、主链改变、页脚挤压、全局字号调整或新增未经授权关系，立即退出 `SCOPED_REPAIR`，改走常规返工。

## 8. 禁止模板化迁移

不得从某一期成功 Overview 推导以下硬规则：固定模块数、固定三栏、固定底部人生线、固定中央工作台、固定颜色含义、固定编号数量或每期都要有平行问题线。可迁移的是内容审计、关系授权、陌生读者复述、返工范围判定和差异验证方法。

用户认可某图的风格或创意时，先记录其起作用的视觉品质与内容关系，再由下一页内容决定对象和构图；风格反馈不等于要求复用该图的笔记本、材料框、栏数或坐标。

## 9. 已通过基线与探索版的比较

用户认可一张清楚的 Overview 后，记录该版 scene、原图和手机图哈希，保留它作为已通过基线。继续探索时，先按 `visual_reasoning.md` 第1节明确改善目标与保留优势，再以相同的内容职责、原图和手机尺度比较。新版本只有在关键案例、边界、阅读顺序和关系准确性均未退步，且确实让核心关系更易理解时，才可替换基线；仅换标题、配色或文字位置不算解释升级。

若隔离审核拒绝的整页后来被用户指出“更清楚”或“接近通过”，先重新看原图、手机图、内容包和拒绝理由，区分可见内容错误与可争议的审美或遮挡推断。记录用户具体认可之处，复核完整页面的阅读结果；没有新的来源风险或全局关系错误时，不以旧分类直接驱动从空白重画或增页。新的局部候选仍需真实渲染、隔离差异审核和用户确认。

连续候选若反复出现小字、案例压缩、把并列途径画成必经流程，或文字容器改排而没有新增解释作用，就停止整页变体，保留已通过版。随后只验证一个明确的局部表达假设；局部成立且能放入最终阅读尺度，再考虑重组整页。
