# 逐页视觉生产协议

本协议适用于每张 Overview 和 Deep Dive。每页独立执行，按顺序完成；协作停点按 `visual_pack_execution.md`：默认三案选择，用户明确改用单案逐页确认或批量制作时按其选择执行，要求先验样稿时只做一页。内页共同执行 `rules/inner_page_module_contract.md` 的页面分区与导航职责；本协议规定其余检查维度和停点，不固定正文构图、图形数量或视觉隐喻。Overview 另须执行 `rules/overview_page_production.md`，Deep Dive 另须执行 `rules/deep_dive_page_production.md`。成图后必须执行 `rules/independent_visual_review.md`，创作者自检不能替代隔离审核。

已批准页面的实际创作先按 `visual_creation_context.md` 装包，由新创作者读取当前内容、实际参考和简洁视觉规则；本协议的完整实现与几何检查在核心成立后加载。内容批准、哈希、来源及固定外围合同持续有效。

## 1. 建立页面合同

先按 `rules/page_content_planning.md` 第 0 节确认页面类型与阅读任务，再从已获用户确认的《内容梳理》《内容拆分》和图片内容规划中提取当前页的 Page Content Pack。以下内容按本页职责选择：总览呈现全文核心框架所需的判断与必要依据，深度页展开具体论证。开始前核验 Content Inventory、Content Split、Content Split Coverage 的哈希以及两次 Human Review 状态，至少包含：

- page role、page question、takeaway；
- 论证路径及各步骤的关系；
- 必留论点、证据、案例、具体对象、关键转折和边界；
- 与 Overview / 其他 Deep Dive 的关系，以及本页不承担的内容；
- 固定页眉页脚、来源、页码和系列术语；
- 内容条目到页面区域的去向表。

Page Content Pack 只规定本页必须解释什么，不提前规定画法，也不得把来源没有的相册、人物场景、产品界面或其他道具写成必留对象。缺失关键证据、边界或内容去向时回到图片内容规划，不进入构图。

成品中的编号、专有名词、引语、数值和案例标识必须来自内容包或明确标注为“示意”。不得为追踪视觉对象而添加看似属于原节目、产品或案例的伪编号；需要表达同一对象时，优先使用一致形态、颜色、图形标记和来源支持的普通名称。

若缺失源于已确认内容产物本身，则按 `rules/content_pipeline.md` 返回《内容梳理》或《内容拆分》并使受影响的下游审批失效；不得在画图时临时从逐字稿补材料。

### 通用标题表达：默认陈述，必要时提问

以下规则适用于封面编辑钩子、总览和深读页的编辑标题，不改写来源中的官方单集标题、直接引语或必须保留的现场问题。

- 默认使用有信息的陈述式标题，点明本页讨论的具体对象及关键关系、动作或张力。只有提问本身承担必要阅读任务、且改成陈述会损失开放性或造成不实结论时才使用问句；创作时说明保留问句的内容理由。规划字段 `page_question` 是内部理解任务，不直接充当成图标题。
- 不只删除问号，也不将“如何、怎样、什么时候、什么才是”机械改成“重塑、解锁、找回真正的自己”等空泛口号。标题应让读者在阅读正文前获得具体信息；涉及个人经验、可能性或特定条件时，保留必要的主体、范围与不确定性，不能为了肯定语气扩大来源结论。
- 标题点明主题或张力，核心结论给出本页支持的判断，副标题补充讨论范围；三者不反复表达同一句话。标题不必提前给出完整答案，结论也不必重复标题措辞。
- 按内容选择具体陈述、动作、条件或并列主题，不固定整包句型、不设问句配额，也不通过机械轮换制造变化。多个独立问答同页时，标题保留其并列范围，不强行合成来源未支持的因果或统一结论。

构图前对照当前内容包核对标题的对象、关系、主体和限定。整包终校再并排检查重复词、连续问句与句型套用；修改已认可页面标题后，重新导出并检查断行、字级、专辑封面避让和手机可读性，不沿用旧图片的批准记录。

## 2. 内容、案例与审美联合预检

**每次出图前**都必须重新完成联合预检，包括初版、重构版和局部修改后重新导出的版本。按顺序核对已通过的完整《内容梳理》《内容拆分》《图片内容规划》与本页 Page Content Pack；以原尺寸重新打开相关正面案例、反面案例和同系列已通过页；重新读取当前 `taste.md` 与 `design_tokens.json`。不能用其中一份替代另一份，也不能把上一版的预检改个版本号沿用。先保存本次 `REFERENCE_PREFLIGHT_Vn.json`，记录当前输入哈希、所见证据、本版构图选择及上一版实图暴露的问题，再创建或修改 scene 并导出图片。至少记录：

- 实际查看的正反案例路径、文件哈希和选择理由；
- 每张正例的具体解释部位、它降低的理解负担，以及本页相应的绘制决定；参考用途不同就分别记录，仅校准笔触的参考注明该范围。完成度与方法分开比较，不以同一句方案描述代替逐图迁移。
- 反例中本页必须避开的构图、线条、图标和信息密度问题；
- 当前方案允许使用的图形语言，以及明确禁用的图形语言。
- `taste.md` 的版本或哈希、当前页采用的原则、明确拒绝的失败模式，以及这些原则将怎样改变构图、对象、图文分工和字号。

审核者在后续阶段读取 `taste.md`，不能补签创作者缺失的审美预检。联合预检没有可核对记录时，禁止进入 scene 构建。

`REFERENCE_PREFLIGHT.json` 必须在 scene 创建前落盘，送审时由 `visual:review:prepare` 比对哈希和文件时间。结构如下；文字须写当前页的具体观察，不能填“符合规范”“参考 E248”等空泛结论。`references` 须逐一覆盖送审命令的所有 `--positive` 和 `--negative` 文件，路径使用绝对路径：

预检不代替真实看图，也不证明质量已通过。若正例呈现的信息密度、具体对象、动作状态或图文协同未在本页体现，创作者应在自检时判为失败；隔离审核者再独立判断。

`module_relations` 必须逐条覆盖本页所有相邻主要区域，不能只填一条示例或把“按顺序阅读”当成关系。每条关系须能回指已通过的内容包；关系尚不确定时先修内容规划，不进入构图。

`relationship_visibility_plan` 另列本页决定性知识关系，不能用“画箭头”“并排放卡片”这类没有对象与状态的画法代替。每条在预检中写明读者将从哪里看见该关系；真实渲染后按 `rules/visual_reasoning.md` 的创作步骤与核心原型完成条件逐条验证。

创建 scene 前，用现有 `main_visual_explanation`、`module_relations`、`relationship_visibility_plan` 和 `text_graphic_split` 回答四件事：**本页主关系是什么；各案例分别承担什么；画面不能让读者误读成什么；图与必要文字合用，比纯文字多解释了什么。** 答案必须指向本页具体对象、状态或证据；若只能写“并列卡片”“箭头流程”或“增加趣味”，先重做视觉解释方案，不新增一套固定页面模板或预检字段。

构图前核对本集 `selected_palette.json` 已由用户选色或持续有效的选色指令生成，并记录文件哈希和实际 HEX；不得只记色卡编号。预检、scene 与真实 PNG 使用同一配色及跨页颜色职责。若用户改选配色，本版预检和相关页面渲染失效，重新生成后再审。

每张内页预检还要记录 `inner_page_modules`：页眉专辑与页面类型、标题/副标题/核心结论、主内容、整包地图与本页提纲、双行来源及独立页码的预计位置与内容来源。当前合同明确锁定的位置予以保留；未锁定或已授权可变的位置按本页内容与主辅权重决定，默认示例不构成右栏要求。本页提纲的每个序号须指向一个可见正文入口；地图主题与页段须和当前页面清单一致。真实 PNG 后逐项复核，缺项或错误不能以“正文内容都在”抵消。

Overview 的预检还须记录 `overview_scope_check`：试排页数下整期问题与主命题、每页职责、最大视觉对象所代表的内容、草图预计的完整页面节目级复述、遮去该对象后预计失去的内容，以及每个核心案例的可见去向。若草图只能讲局部案例、缺少整期问题与其他应用范围，状态不得写为 `completed_before_construction`；按 `rules/overview_page_production.md` 重分职责或权重。真实渲染后，再以当前 PNG 在 `RENDERED_PAGE_CHECK` 中复核完整页面和遮挡后的阅读结果。遮挡是定位依赖的压力测试，不要求其他区域重复案例细节；局部原型的成立也不能代替整页复述。

若人物、手势、物体、动作或机制只能用临场勾画、随手大笔线条、未闭合轮廓或依赖文字猜测来表达，方案在构图前失败，不进入 scene。Excalidraw 的 roughness 不能作为图形完成度的替代品。

## 3. 形成视觉解释方案

遵循 `rules/visual_reasoning.md` 生成并选择候选。选定方案必须说明：

- 读者先看见什么，随后沿什么路径理解；
- 哪些具体对象、动作、空间、状态、逻辑关系或文字结构承担核心解释；
- 图与文字各承担哪些内容，以及为何这种分工比强行画实物更容易理解；
- 每种强调色的语义；同色不得在同一套页面中随机换义；
- 为什么该构图属于当前内容，换一篇文章不能原样复用。

编号只能帮助定位和阅读，不得把论证降格成等权目录。

### 3.1 表达方式选择与重复失败停点

新页面或主结构重构，按 `rules/visual_reasoning.md` 第 1–4 节先推导可观察依据、解释载体与图文分工，写出绘制依据并验证真实整页草图；原型可以使用对象、空间隐喻或文字与关系结构。记录实际 scene/PNG、可见证据、来源误读及整页正常字号容量，核心充分性与完整构建准备度均满足后再制作完整候选。已认可基线的局部修改按限定范围执行，不重开无关原型探索。

原型前预检须早于其 scene；原型后的观察保存为独立构思记录。创建完整 scene 前，重新核对当版完整内容、参考和规范并保存其构图前预检；沿用现有预检字段，不新增正式审核接口。原型检查只决定是否进入完整构建，不能替代整页内容覆盖、隔离判级或用户确认。

同一页若连续两轮因相同的表达问题被创作者或独立审核者退回，停止继续生成整页变体。记录原图的重复失败，重新选择表达类型，再按上述规则验证原型。原型准备与几何勘误均不延长或重置同一方案的返工计数；新的制作范围须有用户授权并明确改进假设。

默认三案模式按 visual_pack_execution 第4节先集中使一案达到完整 TARGET，再完成另两案及方法差异检查；它们是并列选择，不把第二、三案当成第一案的返工轮次，原型不能占完整候选名额。每案仍执行本页联合预检、完整内容与来源核对、原图／390px／灰度实看和独立判级；三案展示门槛执行 visual_pack_execution：至少一案完整 TARGET，其余至少 B，方法差异成立且均无阻断。具体候选审核、替换上限、选择记录与进入下一页的条件见 `visual_pack_execution.md` 第 4 节。若同一候选结构重复失败，仍执行上面的停点，不能借“三案”名义无限重画。

返工次数与限质展示授权按 visual_pack_execution 分开记录；用户要求 TARGET 才展示时，达到次数上限只报告阻断，不自动展示 B。用户明确授权限质输出时，从首次可审核成图算起，最多再做两轮**实质修改**；每轮都重新渲染和独立审核。局部样稿属于该轮准备，不重置计数；几何勘误也不得用来延长同一解释方案的重画循环。若两轮后仍未达到 `TARGET`，停止该页创作，选择经独立审核为 `REJECT-B` 且内容、来源边界与可读性无致命错误的最佳版本作为**限质输出**，向用户展示原图、手机图、可编辑 scene、独立结论及未达标原因。最新一版若为 `REJECT-A`，不得以相对进步交付，可回退到此前符合上述条件的 `REJECT-B` 版本。无合格 `REJECT-B` 时如实标为未完成。限质输出不是 `TARGET`、正式质量 `accepted` 或正式发布通过；记录用户授权与候选哈希。用户可另行接受当前限质版本用于继续工作，按 `visual_pack_execution.md` 记录接受范围而不改写独立等级。用户已明确允许按此上限继续逐页制作时，可在展示限质输出后进入下一页，但正式打包门禁仍须另行满足。

自检中的 `visual_explanation` 需指出当前 PNG 怎样让读者看出论点与关系：图形有效时给图形证据；以文字与逻辑关系为主时，同时给出层级/连接证据及相对简洁图文的实质解释收益。关系可读或来源准确不能单独支撑 visual_explanation / reference_alignment 的 pass。还须逐项说明相邻主要区域为何相接、怎样推进结论，以及读者不会误读成什么关系。只有容器、标签和箭头而看不出具体关系时写 `rejected_by_creator`，不生成正式独立审核包；两轮限质条件确已满足时按visual_pack_execution走专用底账，不伪造通过。

### 3.2 阅读拓扑门禁

绘制前必须在联合预检中声明：整页主阅读方向、段落顺序、每段内部方向、唯一入口、唯一收束，以及禁止出现的跨层回跳。方向由内容决定，可以横向、纵向、环形或中心辐射；不得把任何一种方向固化为模板。

相邻主要区域还要逐项声明内容关系：前一部分回答了什么、产生了哪个自然追问、后一部分怎样推进或补充它。只有位置顺序、编号和“接下来”而不能回答“为什么此处转到这个主题”，属于语义断链。并列案例应以共同问题、分组或对照说明为何并列；不得为制造阅读流而改画成因果链。

- 整页有可追踪的主阅读线；比较区、证据支撑区可以有不同局部方向，入口、邻接和阶段提示要清楚。失败条件是读者需要猜测下一处或遇到竞争入口，不是横向与纵向同时出现。按 `visual_reasoning.md` 检查宏观构图及系列重复，不把清晰阅读收窄为纵向章节堆叠。
- 局部关系正确不能抵消整页顺序含糊。箭头、编号、标题位置和空间邻近必须共同指向同一条主链。
- 每段内部采用稳定方向；需要改变方向时，必须以清楚的阶段边界和入口提示完成，不得无提示跨栏或回跳。
- 做“五秒下一步测试”：从标题进入后，每读完一个区域，遮住编号与箭头仍能指出下一处。不能指出时返回视觉解释方案。
- 阅读拓扑失败属于 `RECOMPOSE`；不得仅靠追加箭头、编号或装饰分隔线修补竞争路径。

### 3.3 颜色职责与手机阅读尺度

每期在构图前记录一份跨页颜色职责表：正文色承载论点、证据与案例；主色建立导航和关键层级；辅色标出本期确有必要区分的另一类信息；弱化色仅用于不承担关键事实的上下文、来源或辅助标签。具体色相和辅色所指的内容角色由本期论证决定，不沿用上一期的含义。每处着色都要能回到职责表，且不能只靠颜色区分因果、并列、选择或边界；同时使用位置、标签、线型或形状。

先给必留论点、事实限定、重要案例和边界分配正文级可读空间，再给导航和装饰分配空间。弱化色与小号注释不能承载读者必须记住的条件或反证。真实渲染后同时看原图和 390px 整页图，按标题、主方法、案例证据、边界和辅助来源分别判断实际辨读情况；不凭估算的像素字号或辅助文字略小直接判整页失败。若关键句确实必须放大才能辨读，先重分栏宽、压缩重复叙述，再以单页真实图的具体损失论证是否按 Overview／Deep Dive 职责拆页，不靠继续缩字解决。跨页审核同一信息角色的颜色与字级是否稳定。

## 4. 构建可编辑页面并真实渲染

1. 先锁定系列页眉、页脚、安全区、来源格式和页码。1200 × 1600 内页使用 `design_tokens.json` 的系列几何合同：左右安全线为 x=80 / x=1120；页眉元信息与页脚来源、页码均为 22px；从真实 PNG 的首末可见字形或图元测量，上下外留白目标约为 64px / 68px，差异不超过 8px。内容驱动的刻意不对称必须在 Page Content Pack 中说明阅读作用。
2. 构建原生可编辑 Excalidraw；文字与其解释的对象相邻。按 `rules/visual_reasoning.md` 第 5 节对照原型和绘制依据，复核实际对象、状态、连接与文字锚点，再做审美精修。绘制前按 `rules/handdrawn_strokes.md` 给每条非文字线或轮廓分配 `stroke_role`：抽象框用 `frame`，简单直线关系用 `connector`，具体对象和有动作感的连接才使用较强笔触；不得在单页脚本中统一覆写 token 粗糙度。
3. 输出 `.excalidraw` 后，先运行 `python3 scripts/check_strokes.py <scene>`；失败则修正角色或数值，不进入渲染。检查通过后再用同一 scene 真实渲染原尺寸 PNG。参数通过只证明角色与 token 一致；仍需在原图及灰度图确认“有笔触的单线”，在 390px 图确认线条没有糊成重影。
4. 同时导出 390px 宽的整页手机预览，实际检查正文、证据限定与边界是否无须放大即可辨读。
5. 正式 scene 只含原生 Excalidraw 图元与可编辑文字；`image` 元素必须为 0，`files` 必须为空。PNG 是同一 scene 的导出结果，不得嵌回 scene。

### 4.1 页面边界几何门禁

- 安全区以当前原尺寸 PNG 的真实字形和图元测量，不能只读 scene 的 `x/y/width/height`。关键文字完全位于左右安全线内；靠右文字的末字再与 x=1120 保留至少 20px 内缓冲。
- 页脚不是正文用完后的剩余空间。构图时先预留页脚分隔线、22px 来源／页码与底部外留白，再分配正文。
- 文字与分隔线、箭头及对象轮廓必须有可见间隔：普通规则线至少 12px，主要对象边界至少 20px。若内容关系要求更近，需通过明确连接点而不是让线贴字。
- 改变标题、正文、页脚的字号、行高或断行后，从改动位置向下重新计算相邻元素，并重新渲染整页。
- 送审前生成临时安全区诊断副本，至少标出 x=80 / x=1120、顶部首可见位置、底部末可见位置和高风险文字轨道。诊断线不得进入正式 scene。

不得以编辑器中的局部视图、代码、元素统计或旧截图代替当前版本的真实 PNG。

## 5. 分层审查

按以下顺序审查并留下可核对记录。前一层失败时先修复该层，再继续。

### A. 内容覆盖

- 每项必留内容都有明确承担位置。
- 重要案例、转折、条件和边界没有只剩抽象结论。
- 本页没有擅自建立来源不支持的因果、顺序或普遍规律。

### B. 整页阅读

- 5 秒能发现标题、主问题和主结构。
- 30–60 秒能沿清楚路径理解结论怎样成立。
- 板块尺度与位置表达主次；编号服务导航，不制造等权卡片感。
- 空间位置表达语义归属；案例专属的事实、解释、追问和边界不能落入另一案例的阅读轨道。
- 并列内容的面积、标题等级、对象尺度、视觉墨量和细节量必须与论证权重一致。
- 颜色种类克制，每种强调色能说出稳定含义。
- 对照本期颜色职责表：重要证据和边界没有被当作装饰性弱化信息；同一颜色没有跨页随机换义。
- 实际阅读路径与构图前声明的拓扑一致；不存在竞争入口、跨层回跳或读完一区后无明确下一步。

### C. 逐句论点

将可见文字分为内容句和导航文字。每个内容句必须承担论点、证据、机制或边界之一，并让陌生读者至少理解以下四项中的两项：

- 谁或什么；
- 发生了什么；
- 为什么重要；
- 由此改变了什么。

发现抽象名词堆叠、无对象动词、缺主语、只有修辞或脱离上下文不知所云时，改写内容，而非只调整排版。

### D. 图形双检

逐个检查所有承载信息的图形：

1. 对实际绘制的对象图，忽略说明文字后主要对象、动作或状态是否可识别；
2. 恢复说明文字后，图形与文字是否共同支持同一个论点；以文字和关系为主的区域，检查关系、层级与证据是否足以直接读懂。
3. 对每条决定性关系，指明当前 PNG 中可见的对象、状态或空间线索；若只能引用解释性长句、抽象标签或导航编号，关系构图尚未成立。文字为主要载体的区域也须让分组、层级和阅读方向体现关系。

核心图形不得依赖读者猜测未说明的隐喻。形态不成立时重画；形态基本成立但名称可能歧义时，可增加紧邻标签。发现一个问题后横向检查全页同类图形。

局部结构、截面或放大图不能独自承担对象识别。若配合必要短标签仍只能看见无归属的零件，先补足完整对象、来源支持的使用场景或整体形态，再用局部图和文字解释机制。

随意勾画的火柴人、手、波浪线、星芒、箭头或大笔路径，不因“能看懂大概意思”而合格。每个承载信息的图形必须具有清楚轮廓、稳定比例、可辨识部件和明确连接点；否则直接返回视觉解释方案。

可清点方格、点、人物、进度段、比例块或重复对象会自动产生数量含义。页面出现来源数字时，图形编码必须与数字数学一致；无法可靠表达时直接呈现来源数字，并使用不产生第二组比例的具体对象建立场景。不得以“只是装饰”解释与紧邻数字冲突的可清点图形。

### E. 规范与机械检查

- 页眉、页脚、来源、页码和安全区符合系列合同；
- 当前获批位置的整包地图标明主题及对应页段、当前主题可定位；本页提纲序号与正文入口对应，主辅视觉权重符合 `inner_page_module_contract.md`；
- 信息框、导航边界和长分隔线在真实原图上读成有笔触的单线；不能以 `check_strokes.py` 参数通过掩盖可见双线重影；
- 当前 scene 的主色、辅色、浅底和正文色与构图前绑定的 `selected_palette.json` 一致；不得残留上一期或 `design_tokens.json` 回退色；
- 正文和关键注释在原尺寸可读；
- 主结论、证据正文、事实限定和边界在 390px 整页预览中可辨读；页脚来源可按系列合同保持辅助层级，但不得承担关键事实；
- 无裁切、溢出、文字压线、箭头穿字、对象遮挡和画布外元素；
- 两张纸、卡片或物件为表现“压住／覆盖”而叠放时，先在 scene 比较上层填充区与下层文字框的交集，再在真实原图和 390px 图检查字形。覆盖面积落在物件空白或被压的内容区域；被覆盖物的名称与必须阅读的事实文字要完整露出，不能以动作语义为由容忍压字；
- 放大字号或改写文字后重新检查换行、行高和邻近元素；
- `.excalidraw` 可解析、元素 ID 唯一、可编辑源文件与当前 PNG 对应。
- 页眉元信息与页脚来源／页码字号一致；上下外留白、左右安全线及文字到线条的最小可见间隔符合第 4.1 节。
- 线条职责成立后仍需单独检查线条几何；书脊、分隔、连接或对象轮廓不得穿过真实字形。删除一条失败分隔线后，重新检查原有栏位和对应关系是否仍有清楚的局部阅读路径。

### F. 整体完成度

按 `taste.md` 与正负参考比较信息丰富程度、图文协同、模板感、简笔画完成度和视觉节奏。机械通过不等于本层通过。

创作者完成 A–F 后只能提交 `submitted_for_independent_review`，不得自行声明视觉通过。独立审核者按高质量成图标准给出 `REJECT-A`、`REJECT-B` 或 `TARGET`。

正式送审所用 `RENDERED_PAGE_CHECK.json` 必须包含 `page_id`、当前 `scene_sha256`、当前 `png_sha256`、`status` 和五项检查。只有五项都附有当前 PNG 可定位的 `visible_evidence` 且为 `pass`，状态才能写为 `submitted_for_independent_review`；任何失败写 `rejected_by_creator`，不得生成审核包。例如：

```json
{
  "page_id": "P01",
  "scene_sha256": "当前 scene 文件 SHA-256",
  "png_sha256": "当前原图文件 SHA-256",
  "status": "submitted_for_independent_review",
  "checks": {
    "content_coverage": {"status": "pass", "visible_evidence": "必留案例和边界分别位于哪些区域"},
    "visual_explanation": {"status": "pass", "visible_evidence": "当前图形、逻辑关系和文字层级怎样共同解释主判断"},
    "reference_alignment": {"status": "pass", "visible_evidence": "与正反案例相比，本页的具体改进与未重现的失败画法"},
    "text_geometry": {"status": "pass", "visible_evidence": "真实 PNG 中标题、右边界和高风险交点的检查位置"},
    "mobile_readability": {"status": "pass", "visible_evidence": "390px 整页上关键正文、条件与边界的检查结果"}
  }
}
```

这个文件是创作者的送审资格记录，不传给隔离审核者阅读；审核包仅保存其哈希。自动校验只保证记录存在且绑定当前文件，不代替对真实图片的判断。

## 6. 返工路由

| 失败类型 | 返回位置 | 修正方式 |
|---|---|---|
| 内容遗漏、论点错误、边界丢失 | Page Content Pack / 图片内容规划 | 补回内容与证据，重新分配页面职责 |
| 内容包强加无来源的视觉对象或具体场景 | Page Content Pack / 图片内容规划 | 删除预设画法，恢复为来源支持的事实、动作与边界 |
| 主结构不解释、模板感强、错误隐喻 | 视觉解释方案 | 重新推导机制和构图；必要时从空白 scene 重建 |
| 阅读方向竞争、跨栏回跳、下一步不明确 | 视觉解释方案 | 从空白 scene 重组为唯一主链，不以补箭头修复 |
| 可清点图形与来源数字冲突 | 图形表达 | 删除伪比例代理，改为数学一致的编码或直接数字记录 |
| 删除分隔后局部层级散乱 | 局部视觉解释方案 | 将窄双列重组为单列或重新分配宽度，不只扩大间距 |
| 句子不知所云 | 页面文案 | 补主语、对象、动作、因果、结果或论证职责 |
| 图形不可识别或与文字错义 | 图形表达 | 重画对象/动作/状态，或在形态成立后加紧邻标签 |
| 来源不足以支持具体场景 | 图文分工 | 使用来源支持的反馈载体、比较关系与正文级文字，不制造人物、地点、产品 UI 或具体个案 |
| 颜色无语义、主次不清 | 视觉语义与层级 | 收敛颜色，重新分配尺度、位置和阅读入口 |
| 字号、压线、对齐、局部拥挤 | 当前 scene | 局部调整并重新渲染全页 |
| 页眉页脚不合规 | 系列页面合同 | 恢复固定结构后重新检查正文安全区 |
| 用户要求保留当前构图，或认为被拒版更清楚、接近通过；重审后问题确可隔离 | `SCOPED_REPAIR` | 冻结基线和允许改动范围，只修目标区域；用 scene 差异、真实整页 PNG 和独立差异审核检查回归 |

`SCOPED_REPAIR` 不是默认捷径。只有页面专属协议规定的进入条件全部满足时才可使用；否则按表中最早失败层返工。一次改动可能引入新的问题。每次返工都重新渲染并重跑受影响层及其后续层，不以“只改了一点”为由跳过检查。

## 7. Human Review 停点

先按visual_pack_execution核对当前授权。默认三案模式展示三张真实图并等待用户选定，当前页选定后进入下一页；单案逐页确认模式等待用户通过当前页；已明确授权批量模式不重复请求继续，逐页记录独立审核与尚未用户验收状态，最终一次展示整包。先验样稿模式在样稿获用户通过前不迁移。

提交当前页时必须先说明：

1. 这期节目整体在讲什么；
2. Overview 包含哪些核心模块；
3. Deep Dive 将怎样展开；
4. 当前页对应哪一页、回答什么问题；
5. 当前版本经过哪些审查，仍有哪些需要人判断的部分。

独立审核为 `TARGET` 时，向用户提供原尺寸 PNG、可编辑 `.excalidraw` 和审查记录，页面状态保持 `needs_human_review`；只有用户明确通过后改为 `accepted`。默认三案模式按visual_pack_execution展示 `TARGET` 或独立判为 `REJECT-B` 的合格选择候选；用户选定 `REJECT-B` 可进入下一页，但当前页保留质量待办，不能改为正式 `accepted`。单案模式的两轮返工限质例外按第 3.1 节处理，必须直接写出等级与原因，不能写成视觉通过。

## 8. 审查记录最小结构

每页至少保存：

- 页面合同与内容去向；
- 版本与反馈修正记录；
- 内容覆盖结果；
- 逐句论点结果；
- 图形双检结果；
- 规范/机械检查结果；
- Human Review 状态与通过版本。
- 创作者身份、独立审核者身份、审核输入哈希和独立审核报告。

总览基准原图见 `rules/acceptance_case_index.md`；检查方法与返工路由以当前总览协议为准，不复制历史构图。

字号层级必须执行 `typography_hierarchy.md`；每轮预检先建立文字语义台账，送审前分别通过整页核心职责、角色字号及真实像素检查。只查数字合法不等于结论选择正确。全流程复盘及交付完整性见 `visual_pack_execution.md`。
