# 逐页创作上下文

本规则处理长会话、连续制作和失败返工时的创作恢复。内容审批与真实图片审核沿用原有门禁；装包、换上下文和执行检查都不产生 TARGET。

## 1. 协调与创作分开

协调者保留整包状态、用户授权、页号映射、已验收资产和待办。新页面的构图与主结构重做交给新建的创作者子代理，使用 `fork_turns="none"`，仅发送本页输入包和实际制作任务。创作者与独立审核者分别建上下文，均不继承主会话历史。这是默认执行方式，不要求用户另开聊天。

子代理不可用时，用同一精简输入包恢复本页；记录未实现上下文隔离，不把该替代当作已验证的稳定性措施。已认可页面的限定修订仍读取基线和允许改动范围。

## 2. 本页输入包

协调者先核验现有内容审批，按 `acceptance_case_index.md` 核对本页必看基准、命中案例与同系列参考，再运行 `scripts/build_visual_creation_packet.py`，传入当前页 ID、内容包、设计 tokens、选定配色和实际正反图片。原页号不同的，显式提供来源页号。脚本绑定当前文件及参考选择规则、检查输入可读并生成中文任务入口；不审批内容、不提炼事实、不设计布局。

创作者先读 `CREATOR_TASK.md` 与 `CREATION_PACKET.json` 并实看绑定图片，完成本页绘制决定后进入正常字级整页草图。入口围绕理解任务、可见依据、主体与支撑职责和参考做法组织；内容与明细保持完整。核心验证读 `visual_reasoning.md`，完整构建与送审再加载相应逐页实现协议。新上下文帮助恢复判断，图片质量仍由实际原型、完整图及独立审核确认。

存在历史页号、导航授权或来源范围变化时，协调者提供 `--page-contract` 绑定的精简当前合同，记录工作页／来源页、工作总页数、导航地图和授权、节目与回听、内容批准记录及未批准补充。由原有门禁核验批准范围；装包不代替批准。缺少影响本页的绑定时，先补交接信息，再完成依赖该信息的模块。原型预检和交接记录另按 `page_visual_production.md` 第3.1节的原型部分执行，不提前加载完整构建检查。

装包前保留本页已批准的完整案例细节和比较依据。内容包只有概括句时，协调者核对已批准明细、来源定位及既有认可资产，提供 `--approved-details` 绑定，记录批准范围与出处。原文用于核实，未批准新事实仍走原内容门禁；已验收图中的已批准事实可以恢复，图的旧布局不会因此成为模板。装包仅绑定明细，不自动扩大审批或判定质量。

首次构图不携带旧失败图、旧拒绝报告、历史尝试清单、上页构图代码或成品对象函数菜单。来源回查、技术实现和局部返工需要时再加载相关材料并记下用途。渲染器、原生图元 API 和文字测量可复用；正文构图、物件组合与元素坐标由本页重新决定。

## 3. 每页恢复实际审美

协调者在当前页合同中绑定已有相邻页实图及用户最新的风格／构图要求；首图尚无相邻图时记录真实可得范围，按 visual_reasoning 的首图分支执行。创作者和审核者都读取实际绑定图片，分别检查本页适配与系列重复；参考的绘制品质不携带其正文几何。用户喜欢一案的风格，只有明确选定当前版本才记录为选图，不能推定其排布是后续模板。

新创作者在原尺寸与手机尺度看实际参考，记录三种不同的信息：

1. 理解收益：读者从哪些部位、对照或位置完成什么判断。
2. 画面质量：主次、对象可信度、局部细节、文字贴合和阅读节奏怎样共同达到完成度。
3. 本页决定：迁移哪种解释职责与质量做法，本页哪项批准内容适合承接；对象与构图重新选择，不复制旧坐标或带入其他内容的事实。同类物件仍可在本页有依据时使用。

正例用于主动决定怎么画，反例用于排除失败路线。不能只列禁令，把剩余内容交给方框和箭头。看过旧观察稿不替代本页实看图片。

## 4. 创作与审核交接

按 `visual_reasoning.md` 先做结构探索与真实整页草图。隔离确认核心充分性与完整构建准备度后，再按当前合同完整构建；外围模块不能决定正文长成几栏。事实边界与诚实示意的画法统一见该规则第3节，不能自行扩大成对象类别禁用清单。交回scene、三种视图、当前输入绑定、参考观察和内容去向，保持待独立审查。

独立审核接收当前工件、内容、参考和规范，不接收创作者自评或希望得到的等级。协调者不补签审美通过。失败后按 `visual_reasoning.md` 第5节修最早失败层；不能由一份拒绝报告断言批准内容无法做出好图。规则输入变化后重新装包和绑定；历史报告、验收与返工底账保留，不倒签新结论。
