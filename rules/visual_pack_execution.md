# 从单张制作到精修与整包交付

开始视觉生产、接到精修反馈、迁移样稿到整包或准备交付时读取本协议。内容流程仍执行content_pipeline及page_content_planning；实际绘制仍执行各页协议。参数引用typography_hierarchy、handdrawn_strokes、footer_source_ranges和design_tokens，不在本文维护第二份数值。

## 1. 确定本次授权与基线

记录用户当前指令的范围、保持项、审批方式和已通过版本。后续指令是在原任务上修正这些项，不默认重启整期分析。

- 默认三案选择：同一页做三种具有实质视觉策略差异的完整图；三案方法成立、各案无内容或阅读阻断且至少一案获得当前完整独立 `TARGET` 后，才展示三张真图及等级。用户选定后冻结其哈希并进入下一页；所选 B 案仍保留质量待办。
- 用户明确改用单案逐页确认：独立审核后展示当前真图，用户通过再继续。
- 用户要求“先改一页，通过后再应用整包”：只制作一张具体样稿，保留已认可资产；通过之前不批量迁移。
- 用户明确要求“完成所有图片，中途不确认”：已通过的内容梳理、拆分及规划仍为前置条件；视觉阶段自主逐页制作、真实渲染和独立审核，最终一次交付，不反复请求继续。该授权不等于每页获用户验收。

### 批量制作的质量关卡

创作与语义审核逐页完成，渲染、导出、复制和归档可批量处理。新页先完成各案的独立原型充分性检查；按第4节集中验证先行案，再完成三案并排方法审核；每页要求的候选均获当前完整TARGET且方法差异成立后，才进入下一页创作。REJECT-B的选择资格只允许如实保存、展示，不赋予批量扩产资格。用户明确指定某个限质范围或选定B后继续时，按其授权记录例外。

进入大批次前，用内容性质不同的少量页面验证流程；数量由本次风险决定，不固定为某一期的三页。单页审核指出的可迁移缺陷须转成下一页的具体预检条件，不能边记录失败边复制同一方法。达到既有返工边界仍未达质量目标时，停止扩产并交实际图与缺口，不通过新增页数或改名重置次数。跨页只复用系列合同、图元能力和渲染工具，正文拓扑按各页内容推导。

独立原型和整页报告通过scripts/check_visual_progression.py校验后，记录本页推进依据。脚本验证当前输入/工件绑定、上下文隔离和报告结论；视觉有效性由独立审阅者负责。没有独立能力时保持待审核。
- 用户要求“最差三页”：实际看当前整包后按具体失败证据排序，列出所选页和问题；不沿用上一轮编号或凭版本名称挑页。

协作方式记在本次生产底账，引用用户原话。用户验收、独立视觉等级、局部精修结论、文件完整性分别记账，不能互相代替。内容门禁变更按上游协议处理，批量授权不取消内容准确性要求。

## 2. 先证明页面值得存在

先按 `rules/page_content_planning.md` 第 0 节核对页面类型职责与全文核心覆盖，再从完整内容拆解建立本页问题、答案、必要解释、依据、边界及相邻页关系。按本页职责判断它是否值得存在，再构图。

内容薄、重复总览或只扩写口号时：合并到对应页，或补入来源中已有且确有解释作用的细节；不得用放大字号、放大插图和增加留白凑页。概览页先验证单页容量，深读页数也由内容驱动，不把本次页数设为下一期目标。

密度来自可解释的内容和关系。文字多本身不判失败；主解释只有重复段落的框、无判断依据的标签箭头或装饰时，重新分配图文职责。按 visual_reasoning 对照同事实的线性文字检查收益，不要求遮去必要文字后图形独自讲完。适合画的具体对象应表现状态、选择、作用或反馈；不适合实物化的内容，用内容专属的对照、条件和关系表达，诚实示意与事实边界统一见 visual_reasoning 第3节。

## 3. 每个版本出图前完成联合预检

包括第一版、局部精修和批量迁移，每版每页核对完整内容拆解、本页内容合同、真实正负向案例、同系列已通过图、taste及当前tokens。按 `rules/acceptance_case_index.md` 选择与解读参考，实际打开图片后记录关键局部、它解决的理解困难及其对本页的影响。参考校准解释方式、层级和完成度，正文构图由当前内容推导。

预检要把 `TARGET` 转成当前页可检查的构图条件：标题和核心结论的层级、主要关系的可见依据、完整内容包的去向、390px 的关键字级及相对参考的完成度。新页面或主结构重构必须先执行 `rules/visual_reasoning.md` 的创作步骤、绘制依据与真实核心原型检查，满足完成条件后再展开完整页。具体原型、预检的时间顺序与记录方式见 `rules/page_visual_production.md` 第 3.1 节；预检中的文字承诺不证明画面已成立。

先保存绑定输入hash的本版预检，再修改scene。输入规范中途变化时，更新受影响页的预检再修改，不倒签旧版本。批量共享的规范观察可以共用，但每页仍记录其内容、对象、风险和迁移范围。

## 4. 单页生产与真实审核

1. 由问题和可观察依据推导图文分工与阅读路径；按 `rules/visual_reasoning.md` 的原型完成条件确认核心充分性与完整构建准备度，再进入完整制作，保留证据与边界。
2. 建立七层文字语义台账：文字ID、原句、职责、所属模块及为什么是整页答案或定位说明。核心结论覆盖主问题，案例结果、侧论、反证和应用不自动升级。按语义再设置字号；没有某层内容时不补造重复句。
3. 完整主体先按绘制依据复核核心关系覆盖与视觉权重，再做审美精修：对象比例、部件连接、证据重心、局部细节和文字归属共同形成高密度编辑信息图。笔触按角色校准 roughness；共用边只画一次。
4. 从本页观点和案例的语义段确定来源时段，先预留页脚，不能统一写整期节目。
5. 真实导出同一scene的原图、390px和灰度图。原生源文件image=0、files为空；全页官方专辑封面按内页模块合同受控合成并记录。
6. 分开验证语义职责、角色参数与实际像素。字号合法仍可能层级错误；放大文字后逐项检查断行、孤立标点、栏宽、邻近线条和页脚。实际查看原图和手机图，灰度用于检验颜色以外的层级。对当前真图重做“视觉增益反证”；若只有标题、标签和方框在解释主问题，自检失败并回到构图，不因机械检查通过而送审。
7. 按独立审核协议提交当前版本。精修审核必须明确范围，不能把“无新增问题”记为“整页TARGET”。只有完整视觉审核才承担整体判级。

### 三案选择的执行与停点

每页新构图先执行 visual_creation_context：协调者保留状态，创作者使用本页精简输入与新上下文。策略差异按 visual_reasoning 判断，不强制同一事实具有三种逻辑机制。先进行结构探索再选择先行案，避免未经探索就把一个弱主体反复加细节。

1. 从同一 Page Content Pack 探索三个有实质视觉策略差异的构图，先集中制作来源依据充分且视觉完成潜力最强的一案，按 visual_reasoning 证明核心充分性与完整构建准备度，再做完整独立审核。该案达到 TARGET 后再完成另两案，最后并排检查三种视觉策略；若先行案失败，按失败层修复，不同时包装三个偏弱主体。内部单案检查不占三案展示名额，也不放行下一页。各案的方法、图文职责和参考依据均由当前内容推导，不指定哪种方法必须先做。
2. 各案先独立验证真实核心原型，再保存完整构建当版预检，制作原生可编辑图及原图、390px、灰度。全部完成后并排检查方法差异与完整覆盖，运行独立审核协议规定的 selection 检查。协议更新时，已完成而未选定的 B 候选可以保留原工件并按当前规则重审选择资格；这不允许新制作的弱原型绕过核心充分性检查。原型不占三案名额或重置返工计数；审核与用户选定分别记账。
3. 每案均由隔离只读审核者按当前规范判为 `TARGET`／`REJECT-B`／`REJECT-A`，报告绑定该案 scene 与三张 PNG 哈希。达到 `TARGET` 的案走正式 `visual:review:prepare` 与后续 closeout。未达到正式自检、但内容和来源正确且无遮挡、裁字、不可读等阻断错误的 `REJECT-B` 案，用标明“选择候选、非正式发布审核”的 `candidate_review_input.json` 交隔离审核；如实记录自检失败，不伪造正式审核包或五项 pass。`REJECT-A` 不展示为合格三案之一。
4. 每个候选位只允许一次改变主解释结构的替换尝试；仍达不到REJECT-B时，展示实际合格数量与阻断。默认逐页选图模式下，三种视觉策略成立、三张均具选择资格且至少一张完整 TARGET 后交用户选择；全部为 B 时保留失败记录、修复方向和当前阻断，不要求用户从失败方案中替流程做质量筛选。策略差异不足也不得展示为齐备三案。批量模式另外执行第1节质量关卡，不因三张B可选而进入下一页，也不无限重画。
5. 用户选定当前哈希后写 `PAGE_VARIANT_SELECTION.json`：三案路径与哈希、独立等级、所选案、用户原话和遗留问题。所选 `TARGET` 仍按正式流程登记用户验收；所选 `REJECT-B` 记为 `selected_for_progress_quality_pending`，即可进入下一页，但不能写成正式 `accepted`、`TARGET` 或 `RELEASED`。整包冻结前按所选页实际等级集中精修；若仍未达 `TARGET`，只有用户明确授权限质交付时才按真实等级交付。

此模式只改变**逐页决策停点**：内容审批、18 页上限、逐案预检、真实渲染、独立判级和正式发布门禁均不放松。用户中途提出某案的局部修改时，按其指明范围重渲该案，避免回到三案全部重做。

## 5. 精修范围与返工上限

### 已验收原生图的正式导入

用户明确授权补齐已验收材料的正式流程、且重新调用constructor会改变获批原件时，使用 `npm run accepted-artwork:import -- --workspace <新工作区> --input <真实工件与批准清单> --editor-review <实际编辑器检查记录>`。这是一条显式迁移分支，默认三案制作规则不变；单案例外必须绑定本页授权，不能补造候选或历史规划。

导入清单绑定当前内容/页序/token、每页四工件和实际单页closeout的完整TARGET与用户批准。原生自由箭头保留真实点列，不伪造端点绑定；构图快照明确标为原图导入，不追认历史构造过程。未提供编辑器检查时仅准备清单，construction保持待检查，不可打包放行。

实际打开全部当前场景并留PNG截图；在副本中通过UI改字、移动对象及原生组、编辑自由箭头，保存真实编辑器导出的前后场景与目标ID，检查换行、碰撞和主体/来源边界。仅当所有当前scene确实没有绑定箭头时，可把绑定端点联动记为不适用，同时保留实际自由箭头编辑证据；存在绑定箭头则必须验证联动。不得以JSON改写或自填pass代替实际操作。整包`package`会重新核验导入、操作证据、共享清单与上游，仍保留当前材料的整包人工验收停点。

先看用户指出的版本与具体缺陷。已有认可或接近通过的基线、且问题可隔离时，冻结内容、关系、布局及本轮不改字段，只修目标区域；若主解释关系本身不成立，则回到内容或视觉方案。

反馈按最早失败层处理：内容/页数问题先修合同；图像没有解释作用先修图文分工；字级倒置先校验句子职责；机械笔触先按对象/信息框/规则线区分；压线先修几何。不能用统一加粗或提高roughness掩盖其他层失败。

用户已授权初版后两轮实质修改的限质输出时，记录同一问题的候选、轮次、修改假设、实图证据与独立判级；两轮后仍只有REJECT-B，则保留其中内容正确、相对最好的版本，明确不足和等级，停止重复重画。不会因改名、换标题或增加候选重新计数。用户明确授权新的修复范围时另行记录改进假设；保留历史次数，不能把新增范围当作清零或无限重开同一结构问题。REJECT-A或内容错误不能限质输出。

上述限质路径只在用户明确授权返工上限后用于保存和说明未达标结果，不能成为下一页的规划基线、整包的常规交付线或“完成 TARGET”的替代说法。没有达到 `TARGET` 就如实保留未通过状态，并在下一页出图前复盘失败发生在内容、关系、构图、字级还是实现层，改进预检；不得把 REJECT 等级当成省去规划的预期结果。

限质展示或继续制作须已有用户明确授权；返工上限只规定停止重复制作，不自动取消至少一案 TARGET 的展示门槛。未获限质展示授权时报告阻断和失败证据，不交全 B 三案要求选图。保留已认可或已选最佳版，未证明改善的探索版不能覆盖它。用户认为被拒版更清楚时，重新比较实际阅读与拒绝证据，不能只沿用旧分类强制重构。

### 获准限质候选的独立审查入口

这是两轮上限生效后的非正式发布审查，不改变正式prepare/closeout的合格条件。自检如实记录失败；若内容与来源正确、几何和手机辨读可接受，仅视觉解释或正例完成度未达标，可建立limited_review_input.json底账交隔离只读审核者。记录用户上限授权、轮次与候选hash；审核输入提供当前内容包、scene、原图/手机/灰度、当前规范及正负案例的路径和hash、创作者上下文ID，全部实际可读取，不提供创作者优劣自评。

审核者独立查看当前图片，报告自己的上下文ID、输入及当前文件hash、可见缺点和完整等级；只有其判为REJECT-B且确认内容/来源/可读性无阻断错误才可限质展示。隔离能力不可用或判REJECT-A时不能用创作者判级替代。该底账不是正式review_packet，不调用要求全项通过的visual:review:prepare或closeout，不伪造五项全pass，不写正式accepted或RELEASED。用户若明确接受当前限质版，另记`user_accepted_limited`、scene/PNG哈希与接受范围；保留REJECT-B和正式发布阻断。精修“无新增问题”不等于完整B判级。

## 6. 样稿迁移与整包精修

样稿通过后提炼用户认可的品质、角色参数与具体禁用方式；不复制对象、坐标、栏数或模板。逐页按职责迁移，并把新图与其基线比较。

整包至少横向复核：
- 页面问题独立、内容足够、总览与深读互补，密度不过稀也不失控；
- 七层语义和字号一致，同一句跨行及并列项一致；核心结论比模块更醒目；
- 对象笔触与排版线各守角色，线条不穿字，共用边不叠描；
- 来源时段覆盖主观点和关键案例，分散段用多个范围；
- 颜色、术语、页码、页眉页脚一致，但不强求页面构图一样；
- 主标题执行 `page_visual_production.md` 的通用标题表达：默认具体陈述，非必要不用问句；并排核对信息量、来源限定、三层文案职责与重复词／连续句型，必要问句按阅读任务保留，不设句式配额。模块标题相对正文醒目，正文定位编号与提纲一一对应，导航底色与当前系列一致；
- 把相邻页面并排看横线、竖线、边框和留白的总体密度：导航线不承担主解释，减线后的文字仍有明确分组、归属和阅读顺序；
- 所有改动页都重新导出并实际复查，不能只看样稿；未动页确认仍引用其有效版本。

批量改字号需要逐页重算局部间距，不能盲目替换数字。把内容文本、图形关系和来源的保持检查与视觉差异审核分开记录。

## 7. 冻结同一交付版本

冻结前做一次**整包首读文案终校**，包括用户已通过设计、只要求检查文字的情形。按页从主标题读到页脚，假设读者没听过节目：能否认出谁在说、例子是什么、它支持结论到哪一步、相邻板块为何接续；“现场问答”“案例”“延伸讨论”等栏目是否让读者从页内认出具体提问或讨论对象，而非只看到栏目名；第一次出现的专名、缩写、网梗和隐喻是否有足够识别线索。节目口述、个人见闻、编辑推断及未核实结果要在相应句旁保留主体与语气，不能让页底边界替醒目断言收回范围。总览页此类栏目按 `rules/overview_page_production.md` 第 4 节核对内容身份、关系与容量。

文案歧义可只改必要文字并冻结已通过的构图；核对修改没有改变案例归属或图文关系，再从当前 Excalidraw 重新导出原图、390px 和灰度图，逐行看实际字形、栏界与相邻图元。记录本轮文字修订及其审核状态，区分用户对设计的通过、编辑首读自检、独立视觉等级和用户对新文案的验收；改字不自动升级页面判级，也不能把旧 PNG 与新 scene 混装。

先选每页最终候选，再建立当前版本清单。保存页面问题/角色、来源时段、当前scene/原图/手机/灰度四hash、当前tokens版本与hash、审核范围/报告hash、整体评级的依据版本以及用户验收状态。

历史审核、旧tokens和旧统计只放历史记录；不得复制成当前规范或让manifest残留旧版本说明。若仅做局部审核，旧整体评级只能标为基线历史信息；正式门禁仍须当前完整审核及用户验收。

目录包含可编辑源、原图、手机/灰度、已审批内容与来源映射、当前审查、复盘、预览入口和伴读文案。伴读文案执行 `rules/public_copy_production.md`，核对分享主线、实际交付范围、字符数与忠实度，默认标题、正文及话题合计800个字符以内，用户另有要求时遵从。禁止把作者个人经验写成普遍保证或模拟听众体验。

正式 `npm run package` 会阻断缺失或失效的小红书文案。若当前只能制作集中查看包、限质包等非正式归档，不能绕过这项交付物：先运行 `npm run public-copy:check -- --workspace <节目目录>`，把草稿、终稿、复核记录、记录 JSON 和门禁 JSON 放进归档的伴读文案目录；再运行 `npm run public-copy:bundle-check -- --workspace <节目目录> --bundle-copy-dir <归档伴读文案目录>`。检查失败时停止打 ZIP 和宣称整包齐全；来源伴读附录不能代替小红书文案。临时单页试稿尚未作为最终交付时，不提前强制生成伴读文案；用户只要求一页总览作为最终交付时，仍须配套标题、正文和话题，并按这一张图的覆盖范围复核。

在所有文件完成后生成ZIP，比较目录与ZIP的文件集合和逐文件hash。补写文案、改README、刷新报告或manifest后，必须更新ZIP再检查；不能只验证压缩包存在。检查预览入口、页序、文件数量和链接；不同版本的文件不能混装。

交付报告分别说明：完成内容、真实验证、当前限质问题及未验收项。局部精修通过、全包文件完整或用户要求直接制作，都不表示全包TARGET或用户验收通过。

## 8. 中断恢复

从生产底账恢复最近有效的内容合同、基线、候选、审核及待做项。额度/审批/渲染故障中断时记录最后成功步骤和未执行动作，不另造新流程或自动换运行时；用户要求继续后从未完成处恢复。引用当前文件hash，不能拿上次截图冒充恢复后的输出。
