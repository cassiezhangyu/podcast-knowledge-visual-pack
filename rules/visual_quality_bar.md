# 视觉质量底线（R1–R15）

> **v0.5.0 定位**：R1–R15 是护栏，不是设计方法。设计方法见 `rules/overview_page_production.md` §0（解释底账 → 视觉中心 → 固定审稿顺序 解释力 → 构图层次 → 颜色／线条／细节）。
> **检查脚本只是下限**：`check_strokes`、`check_typography` 与独立审稿 TARGET 都只是底线，查不出文字碰撞和制作过程标签；最终判断必须亲眼并排看 PNG（成图 vs 质量锚点）。

每张图在作图前读、出图后逐条自检。任一条不过，不得交付，也不得在审核里给 TARGET。数值来源只有 design_tokens.json（text_levels、nav_panel、palette_duties、export、stroke）。

- **R1 视觉中心＋眯眼测试＋禁空带**：每页只有一个视觉重心。它是全页最大、颜色最重的图形，承载本页核心框架。缩到 390px 再眯眼看，1 秒内只看到一个焦点，其余模块是卫星。看到两个或更多同权重块就算失败。**密度硬规则**：中心对象与卫星模块必须放大到填满页首导航与页脚之间的可用正文区；模块之间、中心与页脚之间不得出现大片无信息空带（连续 ≥80px 高的纯白水平带、且该带两侧无内容模块，即失败）。留白只服务分组与节奏，不对标“空气感海报”。密度与完成度对标 `examples/positive` 中最接近的正例（如 EP88），宁可略挤，不可稀。
- **R2 可辨认隐喻**：用了隐喻（树、桥、阶梯、循环……），陌生人就要在缩略图上叫得出它是什么。树要有树干、根和一整团树冠，不能拿几个圆加一张网络代替。框架标签用小标签贴在对象上（引线 ≤40px），不能用大圆盖住对象本身。
- **R3 四级文字层级**：L0 是整页结论和模块标题；L1 是每个模块唯一的关键句（加粗，主色）；关键句的引导字（如“破＝”）用辅色深阶、32px、加粗；L2 是解释和例子（深灰、常规字重）；L3 是图注和免责（浅灰）。任何层级不低于 22px，层级差靠颜色和字重拉开。每个模块必须恰好有一个 L1。
- **R4 主辅色分工（主色主导）**：主色负责主命题、模块标题与编号、主链关系、焦点信号及导航区浅底与边框（细则见 R4b；非焦点轮廓用中性深灰）。**辅色只作极小强调**：引导字深阶、编号圈描边、小圆点、短下划线、小图标局部、对比对象上的细线或叉号——不得用辅色／`accent_surface` 做大面积底、大色块面板或导航区填充。辅色有色像素占比 **≤约 8%**（旧值 15–30% 已废止；实测若辅色块抢过主色视觉权重即失败）。浅阶辅色不能当文字色，有色文字对比度 ≥4.5:1。
- **R4b 颜色职责**：**颜色职责（v0.5.0，Cassie）**：底色与对比一起决定——太素（全灰无重心）和满页蓝（每层都蓝）是同一条规则的两端。正文、解释、机制内标签用墨色（`colors.text_primary`）；非焦点对象轮廓、分隔线用中性深灰（L2 `#3E4552`），排线用浅 hatch 阶作质感。主色用于：整页结论／主命题、模块标题与编号圈、主链关系箭头、一个焦点信号（如温度计液柱）；主标题用墨色或主色按判断。**颜色重量（v0.6.0）来自有含义的实心信号块**（实心比例条、热格、拥挤 vs 空池对比、价差填充），不是把正文或轮廓改成主色；不再用主色墨迹占比作指标（不同色板不可比），改为与锚点并排目测 + “页面至少有一处承载含义的实心信号块”检查；正文与非焦点轮廓也用蓝（蓝色铺满每一层）= REJECT。辅色只作风险／不做标记，≤8%。
- **R5 导航区**：导航区的**任务**固定（整包内容地图、本页提纲、关系说明＋怎么读），**位置、形状、尺寸**按本期本页的版式需要决定：可以是窄竖条、页首／页尾横带、紧凑角块或整宽面板。导航不得挤占视觉中心的空间；中心对象需要宽度时，先压缩导航。正例展示的是导航要完成的任务，不是固定位置或尺寸（v0.4.4，Cassie）。本页提纲、怎么读、全文大纲放在一个与正文分开的导航区里。面板用**主色浅阶底**（由本期 primary 派生的高明度低饱和 tint，如 indigo 的 `#EEF1F8`）加**主色中阶细框**，跟正文模块分开——**禁止**用辅色／`accent_surface`（桃、沙、杏等）做导航底。编号圈可用辅色描边作小强调。三行内容不能重复：提纲写“编号＋模块名＋（角色）”，怎么读写本版构图的读图路线，大纲写读者语言的节目顺序。
- **R6 固定“怎么读”**：总览页和深入页都必须有一句“怎么读：”。按读者实际的视线顺序写，先读哪里、往哪个方向读、每部分对应什么，例如“先找中间的树，从下往上读——种子是破，树干是立，树冠是行”。不能写成“先看③再回①②”这种跳读。
- **R7 无过程文字**：图上只出现读者需要的内容。版本号、方案名、页码规划、制作说明、“主视觉区”这类结构标签一律不写。**禁止把编辑／制作术语写上成品**，例如「金句」「主命题」「可视化重心」「本轮范围」「卫星模块」——命题句子本身可以出现，但不能用「金句」这类标签框住或标题化；提纲里用读者语言（如「为何写纪律」「三步方法」），不用内部术语。
- **R8 4K 矢量导出**：交付图是 `render:checked` 输出的 `*-4k.png`，即 scene 按 export.scale=2.4 做的矢量重渲（2880×3840），品牌图按同比例合成。1200 和 390 的图只用来检查。禁止放大 PNG。
- **R9 亲眼看每张 PNG**：交付前，执行者自己打开每张原尺寸图、390px 图和关键局部，逐条对照 R1–R15 记下结果。没看过图，不算完成。
- **R10 同类问题扫描**：用户指出一处问题后，按同一条原理把全页、全部方案扫一遍，例如“引导字太浅”就要连带检查所有标题、标签、关键句和导航文字。报告里列出“已发现同类 n 处、已改 n 处”。
- **R11 稳定手绘线**：所有线条和填充都用 stroke.role_settings 的手绘参数，不能退成平直的 SVG 或几何图，也不能抖成乱线。参考 ep88-p13 的线感。
- **R12 手工排线**：Excalidraw 的 hachure 填充可能只渲染第一个图形，排线一律在形状内手工生成（`scripts/` 的 hatch 辅助或等效代码），渲染后用眼睛确认每个应排线的形状都有线。
- **R13 三个方案同等完成度**：要求出多个方案时，三个方案的构图要有本质区别（主视觉形态不同），完成度、文字量和检查程度相同，不能一主两陪。
- **R14 严格对照正例**：审核时把成图和 examples/positive 中最接近的正例并排比较。只有在信息量、视觉重心、手绘质感、层级都不低于正例时才能给 TARGET。做不到就给 REJECT 并写出差在哪里，不能放宽评级。
- **R15 禁止 Box Everything**：不得用等权大方框／圆角卡片把正文装进一排或一列「文字容器」。边框只允许承担语义——真实对象轮廓、对象状态、约束边界，或导航区／风险提示这类克制阅读区域。仅为整理排版而套的框（步骤卡、模块卡、金句卡、对照卡等）一律拆掉，改用留白、字号与字重层级、位置、主色／中性浅底、分隔线或开放主轴表达分组；减少边框后阅读顺序仍须一眼可读。缩到 390px 若满眼是大方框网格，即失败（与 taste REJECT-A「Box Everything／文字装盒」同条，升为硬底线）。

- **R16 视觉中心＝一张大的连通机制图**：中心模块是一张连通的机制图（流程／对照／状态切换／数量比较），视觉分量明显重于其他模块；几个分开的小机制并排不算中心。
- **R17 画机制，不画文字**：每个模块至少有一个承载意义的图（流程、对照、状态切换、数量比较）；装饰性小图标不算。
- **R18 交付前必须对照质量锚点**：成图与质量锚点（如 EP40 总览）同尺寸并排；更弱就内部继续迭代，不交付。
- **R19 补丁失控即重构**：连续两轮修补都引出新的连锁问题时，停止打补丁，从空白画布重新构图。
- **R20 正例用判断不用形式**（v0.4.4 保留）：每个借鉴的选择都要写出理由；照搬版式／坐标／模块形态 = REJECT。
