# 正负向案例库持续维护

制作、审核、反馈或日常发现值得学习／警惕的知识图时读取；也支持独立指令“收录这张图为正例／反例”“补充该案例的判断依据”“停用这组案例”。只维护案例、索引与安装副本，不改变当前页面审批、制作范围或质量等级。

## 收录与分类

1. 实际打开原图或用户提供的截图，指出具体位置、解释收益或缺陷、适用问题与判断范围。原图优先；截图如实记录裁切范围与尺寸，不推定全页质量、来源事实或可编辑性。
2. 计算文件SHA-256，查现有记录避免重复收录。同图有不同优缺点时，补充同一记录的适用标签与证据，不复制成互相矛盾的全图评级。
3. 保存原字节与 `case.md`（格式见 `templates/visual_case.md`）：有明确用户认可／否定，或当前真实作者自检及可定位证据的，可按实际范围进入 `examples/positive/<案例ID>/` 或 `examples/negative/<案例ID>/`；只有创作者观察、缩略图印象或判断待核的，先进入 `examples/candidates/<案例ID>/`。记录分别标明 `active`、`candidate`、`retired`，并区分用户反馈、作者自检和观察意见；外部图未核来源时只作视觉参考。
4. 在 `acceptance_case_index.md` 补充适用问题、文件入口、认可／诊断范围、可迁移做法与不可照搬内容。候选另列候选区，不进入正式选例表；原图、可用手机图和scene各自保存路径、尺寸与哈希，缺少的如实注明。

明确反馈可直接按其范围登记，不为每张已明确认可或否定的图重复索取确认。局部风格认可只成为该风格的参考；独立TARGET不等于用户验收；REJECT仅在已定位的缺陷上提供负例。新正例不自动替换必看基准，新负例不自动生成通用禁令，基准变更与长期审美升级须有明确用户决定。

## 修订、转正与停用

### 从案例提炼规则

先区分通用质量要求、用户／系列偏好和本页具体修法。提炼前说明它改变哪个容易出错的决定、何时触发、怎样观察完成、何处不适用，并查现有规则是否已承担该职责；已有规则够用时修入口或补例，不重复增条。单页证据可支持明确范围的案例与窄修正，不证明跨题材普适。物件、色值、栏数、坐标及局部阈值留在案例或当前合同，不自动升为通用要求。

规则验证同时检查原失败与合理例外，允许解释有效的必要文字、容器、并列和图文共同承担含义。新规则误伤合理表达时收窄或撤销；无决策价值、重复或冲突条文在检查调用与合同依赖后合并或替换，历史证据保留。规则优化不另行授权新增代理。

补充反馈时更新同一 `case.md` 的依据、范围与状态。候选有足够依据后登记到对应正／负目录并更新状态与索引；调整目录时保留旧路径映射及可读取的原字节，已绑定旧路径的当前预检／审核包重新绑定后再使用，不补签过去审核。发现案例不再适用或分类错误时标 `retired` 并退出正式选例，保留原图与历史依据，不静默覆盖或删除历史已绑定文件。涉及必看基准时同步索引及其他必读指针；替代基准未确定时注明待选，不静默改用候选。

## 完成检查

以runtime仓库的 `examples/` 和索引为维护源，同步实际Skill安装入口的本次变更。逐项核对原字节哈希、去重、状态依据、适用范围、索引路径和受影响引用；变更说明列出新增／修订／转正／停用项，无候选或现有案例变更时如实说明。私有或未明确公开范围的素材保留在项目内，不混入公共发布包；公开范围沿用 `LICENSING.md` 与 `examples/USAGE_NOTICE.md`。
